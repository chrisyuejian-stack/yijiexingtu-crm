# 阶段 3 前端对接说明

当前依据：冻结接口 v0.3.4 第 0–8 节及用户三项补充。基线为精简融合源码，阶段 2 前端文件本阶段未改。新设置页面由前端继续制作。

[前端接口示例.json](前端接口示例.json)提供同一个本地演示场景中的44组真实请求和响应，覆盖本阶段每个接口的方法；key索引在文末。它们直接调用正式 Worker 服务并使用本地数据库/R2模拟，未手写成功响应。测试用户名、手机号、ID和临时密码均是虚构夹具。

## 通用调用

沿用登录返回的 api_base：根会话 `/api`，机构路径会话 `/{slug}/api`。下面省略此前缀。机构身份从会话确定，不传 tenant_id 或 created_by。会话 Cookie 由浏览器处理。

集合和列表不同：subjects 返回数组；stage-rules/calendar/course-rules 返回带version的完整对象；课程、阶段、班型、图库、修改卡片列表返回 `{items,total,next_offset}`，支持offset/limit，limit最大200。POST创建资源返回201（subjects导入返回200），PUT/PATCH保存返回200。

PUT/PATCH必须带当前version，DELETE也提交version以防并发删除。冲突409 `version_conflict`，`details.latest`是当前完整对象。错误体为 `{error,message,details?}`。缺失和跨机构资源统一404 `not_found`；v0.3.4明确例外：course-rules的阶段或课程引用不合法返回422。其他普通字段校验错误422。机构停用/到期仍按阶段2规则返回403 tenant_expired并保留会话。

新DTO不返回tenant_id。旧CRM接口既有字段保留，例如员工me原来已有tenant_id，不在本阶段删除；家长绑定link和ops的ai_override已去掉该键。前端机构选择、品牌和api_base继续沿用融合版约定。

## 学科模板与报价

- GET `settings/subjects`；POST同路径 `{key}`。key只有 music_interest/music_exam/art_interest/art_exam。模板课程、阶段、节点、维度、内容结构来源为template；价格为null，由机构填写。重复导入不覆盖同名项目。
- GET `settings/courses?subject=&group=&q=&include_inactive=0&offset=0&limit=50`，额外返回服务器的 `price_list_rev`。报价库写入后该版本更新。GET `settings/courses/{id}`也可读取单项。
- POST `settings/courses` 创建；PUT `settings/courses/{id}`提交完整课程与version；DELETE同路径 `{version}`停用，原价格和历史ID保留。
- 课程字段：subject/group/name/form/minutes/duration_text/pricing/optional/course_type_id/active。source和ID由服务器维护。minutes为15–480整数，或用duration_text说明“半天/全天”；不改变原排课课程的30/45/60限制。
- pricing为null或 `{mode,amount,unit_label?}`；mode取per_unit/per_term/per_semester/per_month/package；package必须给units_per_package。amount以元传入，最多两位小数，数据库保存整数分。缺少prices.read时课程DTO不含pricing。
- 可选费用通过optional=true单列，group可用“可选费用”；和课程方案的自动排课、课时包生成没有联动。

## Excel两步导入

同一路径 `POST settings/courses/import`：

1. 预览用multipart，字段file为xlsx。示例文件：[报价导入示例.xlsx](examples/报价导入示例.xlsx)。表头为“学科、课程组、课程名称、形式、时长分钟、时长说明、计价方式、金额、每包课时”；还可提供“排课课程ID、可选费用”（后者填“是”）。学科/form/mode填接口key。
2. 响应含preview_id、expires_in=1200、rows（Excel行号、规范化course或errors）、can_commit、price_list_rev。预览不写报价课程。
3. 用户确认后再次multipart，传preview_id和confirm字符串“true”，无需重传文件，也不传改写后的行。只采用服务器保存的预览内容。坏行必须修正后重新上传；预览不能跨账号使用，已确认不能重复导入，价目表版本变化需重新预览。

每次1–200行，xlsx最大750KB。44组JSON示例里multipart被记为字段与文件元数据，真实上传请使用FormData并让浏览器生成Content-Type边界，不发送JSON文件对象。示例PNG与xlsx对应实际演示使用的内容。

## 三类集合设置

GET与PUT使用同形完整对象，PUT整体替换：

```json
{"version":1,"rules":{"exam_sprint_before_grade":false,"insert_holiday_camp":true,"art_exam_end_after_school_exam":false,"art_transition_stage":false,"mock_exam_schedule":false}}
```

stage-rules的rules必须五个key齐全且都是布尔值，不能有未知key。这里的值仅示意；默认开关来自导入的学科包，没有模板时GET是 `{version:1,rules:{}}`。

```json
{"version":1,"region":null,"items":[{"key":"grade_exam","name":"考级季","months":[1,7,8]}]}
```

calendar的key不重复、months非空且为1–12整数，region可为null。被阶段锚点引用的节点需先解除阶段关联再移除。

```json
{"version":1,"items":[{"stage_type_id":"stg_…","required":["crs_…"],"recommended":[],"exclusive":[],"units":{"min":6,"max":20}}]}
```

course-rules中每个stage_type_id最多一条；阶段、课程引用必须属于当前机构且存在。不接受裸数组，不做局部合并。空集合首次GET的version为1；模板初始化也是1，之后成功写入递增。

## 阶段、报告班型与学员

GET/POST/PUT/DELETE `settings/stage-types`；PUT/DELETE的id放body，并带version。阶段字段为subject/name/default_months(min/max)/anchor/anchor_node/offset_months/order/active，anchor取start/normal/on_node/before_node/after_node；节点型锚点引用本机构calendar的key。

GET/POST/PUT/DELETE `settings/report-classes`；PUT/DELETE同样body带id/version。字段为subject/name/dimensions/options/active。维度key用小写字母开头、字母数字下划线，创建后保持编号；改名改name；删除后该key不能复用。dimensions项包含key/name/order/feedback_tags；options为compare_previous/mock_exam/require_artwork/renewal_suggestion。老师只读维度，不返回班型发布选项。

学员通过原 `data/students/{id}` 保存report_class_id，必须是本机构报告班型，可用null清空。未填写nickname时传空字符串或省略该字段；机构手填的值原样保留。nickname空值按姓氏自动生成，例如周同学、欧阳同学；英文或无法判断时保留姓名。旧字面“X 同学”由0020及导入保护修正，机构手工称呼不会被覆盖。parent_consent_media沿用阶段2写布尔、原学员DTO读0/1。

## 档案、品牌与图库

GET/PUT `settings/profile`，完整对象字段：version/introduction/features/address/class_hours/contact_phone/selling_points/teachers；features与selling_points是字符串数组，teachers是 `{teacher_id,introduction}` 数组，关联老师须属于本机构。档案是后续AI事实来源，示例中的介绍只是本地模拟资料。

GET `settings/brand`；PATCH只接受 `{version,primary_color?,qr_image_id?}`。其他字段一律422；新选二维码需当前机构图库中的可见图片；已经引用的二维码被隐藏后仍可保留，不影响只修改主色，不存在或跨机构返回404。name/logo/login_bg只读，来自平台品牌；qr_url为需要登录的图库链接。

GET `gallery?tag=&offset=&limit=`；POST multipart字段file、tags（JSON字符串数组）。只支持PNG/JPEG/WebP，最大2MB；服务端记录真实文件头中的宽高。上传返回id/version/url/width/height/tags/parent_consent_media/hidden。标签含“家长已同意展示”时，图库同意标志为true。

PATCH `gallery/{id}`提交version/tags；GET `gallery/{id}/file`需要有效会话和设置读取权限，返回图片二进制。DELETE提交version：有品牌、方案或报告引用时只隐藏，历史URL仍可使用；无引用时删除R2对象、列表和读取不再提供。用户上传图存储在带机构ID的私有命名空间。家长或分享链接读图按后续对应内容接口校验，本阶段没有开放图库给家长。

## 修改卡片

POST `settings/changes {suggestion_id,payload}` 只建立pending卡片，不改业务设置；主管通过GET `settings/changes?status=pending`读取并处理：POST `settings/changes/{id}/approve`、reject、revert，请求体可为 `{}`。只有主管审批、拒绝、撤回；涉及价格需要prices.write。

payload按冻结示例使用ops中的update，实体白名单course/price/stage_type/stage_rule/calendar/course_rule/report_class。course与price等单项通过id确定目标；calendar通过key找节点；stage_rule的field为规则key；course_rule通过key找stage_type_id。每项须提供field/from/to。side_effects和affected用于提示，不作为额外写库指令。

提交时记录目标快照；审批再校验版本和引用，全部原子写入。目标被编辑后返回409 change_stale，不能强行覆盖；撤回同样检查审批后的版本，成功后回到修改前内容但版本继续递增。

**阶段3交付普通卡片保存与审批服务。`POST /api/ai/settings/propose` 的模型调用、建议生成、配额与幂等在阶段5实现。**本次44组示例在调用提交接口前由本地夹具放入settings.change建议记录；该前置夹具已在素材采集脚本中明确标注，不代表已有AI生成接口。前端现阶段可先用真实响应制作模拟页面。
