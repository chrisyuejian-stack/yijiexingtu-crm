# 阶段5前端对接说明

依据冻结接口 v0.3.6。本文说明后端已交付的入口；完整请求体、实际状态码和响应见同目录 `前端接口示例.json`，以及 `verification/*http*.json` 原始记录。所有示例来自本地 HTTP 调用，模型输出用本地模拟生成，不代表已连接真实模型。

## 地址、认证与权限

下表用根会话的 `/api` 表示；机构路径会话换成 `/{slug}/api`，始终使用登录返回的 `api_base`。沿用 Cookie、Origin 校验和普通 JSON 请求。新增对象不含 `tenant_id`。不存在或跨机构资源返回相同 404。机构停用/到期先于用量判断，返回 403 `tenant_expired`。

招生内容读取/写入使用 `content.read/write`，主管、顾问按现有权限矩阵使用；个人角色不能借这些接口读取内容。AI 同时校验 `ai.use`、对应业务写权限、机构状态和模块。关掉 `content` 不影响 `plans`，文章样式在只启用内容模块时仍可读取。

## 招生内容

| 方法 | 入口 | 用途 |
| --- | --- | --- |
| GET | `/api/content?type=&scene=&status=&author=&offset=&limit=` | 内容列表，返回 items/total/next_offset |
| POST | `/api/content` | 新建，201，作者和时间由服务器生成 |
| GET | `/api/content/{id}` | 读取完整内容 |
| PUT | `/api/content/{id}` | 保存，必须带当前 version，冲突409含 details.latest |
| DELETE | `/api/content/{id}` | 软删除；可带 version 防止覆盖他人修改 |
| POST | `/api/content/{id}/status` | `{version,status}`，人工标记状态 |
| GET | `/api/content/scenes?subject=` | 学科模板中的场景 |
| GET | `/api/styles?doc_type=article` | 当前可用文章风格及 manifest |
| GET | `/api/styles/{pack_id}/versions/{v}` | 读取锁定历史版本，停用后旧文件仍可渲染 |

内容类型为 `article/moments/xhs/poster_text/group_notice/event_invite`，状态为 `draft/ready/copied/published`。`published` 是人工标记，并未向公众号、小红书等外部渠道自动发布。普通编辑和状态改变均留下不可覆盖的修订记录。

内容包含 `type,subject,scene,title,style,brief,sources,blocks,applied_suggestion_ids`，响应另有 id/version/status/author_id/created_at/updated_at。风格保存 `{pack_id,pack_version}`，不随风格包停用或升级漂移。新建默认使用起步文章风格 `stp_article` 的 1.0.0；已有 `stp_folio` 及其版本未改。

`sources` 只提交勾选项：`{profile:boolean,course_ids:[],gallery_tags:[],prices:boolean}`；档案、课程、图库等真实资料由服务器取。客户端补入的 profile_data、价格或其他资料不成为可信来源。未勾价格时不向内容模型提供价格；隐藏图库不进入新选图范围。历史内容已引用的隐藏图片可以继续保存。

七种块均是 JSON 数据，不能存 HTML：

| type | 字段 |
| --- | --- |
| heading | text、level（2或3） |
| paragraph | text |
| list | items（字符串数组）、ordered（布尔） |
| table | rows（字符串二维数组，首行为表头、列数相同） |
| quote | text |
| image | image_id、caption |
| divider | 无额外内容 |

AI 块可以带 `basis:[0,...]` 引用该条建议的依据下标。普通业务保存按块白名单重新校验，不把这些临时依据字段当成 HTML 或业务事实保存；采纳追溯通过 `applied_suggestion_ids` 和专用建议记录保留。图片必须属于本机构。

## AI 请求与响应

所有模型 POST 带 `Idempotency-Key: <UUID>`，业务请求中可带 `tier:"fast"|"deep"`、`instruction`。请求中的 `context` 不替代服务器资料。收到响应后由人选择，再调用普通业务保存；AI 不替前端保存方案、内容或设置。

| POST入口 | 请求关键字段 | 建议 kind / payload |
| --- | --- | --- |
| `/api/ai/plan/fill-from-consult` | plan_id | plan.fields，fields 数组含 path/value/quote |
| `/api/ai/plan/stage-courses` | plan_id、stage_key | plan.stage_courses，variant/lines/computed |
| `/api/ai/plan/polish` | plan_id | plan.text，fields 数组 |
| `/api/ai/plan/adjust` | plan_id、page、instruction | courses页为plan.stage_courses，其他页为plan.text |
| `/api/ai/content/outline` | content_id | content.outline，sections |
| `/api/ai/content/section` | content_id、section_key | content.section，section_key/blocks |
| `/api/ai/content/versions` | content_id | content.versions，versions.short/medium/long |
| `/api/ai/content/rewrite` | content_id、block_index、mode、text | content.rewrite，mode/blocks |
| `/api/ai/content/fact-check` | content_id | content.fact_check，items |
| `/api/ai/content/images` | content_id | content.images，items（section_key/image_ids/reason） |
| `/api/ai/settings/propose` | instruction | settings.change，经现有修改卡片流程采用 |

以真实示例 JSON 为字段形态依据，接口冻结原件的 §4.3.4、§4.4.2 为最终规范。各条建议的 target 由服务器绑定本次资源和位置，不能通过模型返回另一个机构或文件 ID 改写。

成功响应始终含 `suggestions`、顶层 `warnings`、`usage:{tier,used_today,limit}`，每条建议也带 basis 和 warnings。`unsupported` 表示无法从本次资料中核实的文字，前端应显式提示人工确认；服务端不会把模型自称的 match、来源或金额直接当作已核验事实。事实核对会按当前真实来源重算。文字事实判断采取保守标记，不能替代人工审稿。

模型成功但没有通过校验的建议：200、空 suggestions、warnings，仍计一次。模型错误、超时、协议解析失败：502 `ai_unavailable`，不计次。模型内部重试共用快速45秒/深度90秒截止时间。前端超时应留足服务端完成和返回时间，不应把网络超时等同于未计次。

文字修改只接受冻结白名单。阶段路径例如 `modules.path.stages[key=stk_...].goals`，课程行路径按 `line_id` 定位，不能用数组下标。consult 派生字段必须能核对咨询原话。AI 分数字段一律剔除。

课程建议中，旧行沿用稳定 line_id 和原价格快照；新行用 tmp_ 临时 ID 和当前有效报价，computed 由服务器统一计算。不要把旧行先删除再当新行重建。采用后通过原方案 PUT（带当前 version）保存；整体换价仍用已有 reprice。推荐被过滤时，排第一的合规备选自动成为推荐。已发送/签约的历史修订不被工作稿 AI 改动。

采用设置建议仍调用既有 `POST /api/settings/changes`，再按权限审批；AI 端点不会直接改设置。普通内容/方案保存也会再次校验采纳 ID、资源归属与当前引用版本。

## 重试、用量与平台配置

网络重试和重复点击复用相同 UUID、相同请求体；主动“重新生成”才换 UUID。同键不同请求体422 `idempotency_mismatch`；进行中409 `in_progress`；完成后直接重放。10分钟后凭重放凭据恢复原建议顺序、原warnings和原usage快照，至少2天内不重新调用模型或扣次。最新当日用量另查 GET。

`GET /api/ai/usage?date=YYYY-MM-DD` 不调用模型、不占额度、不需要幂等键；非主管响应不含其他账号明细。默认 fast80/deep50，按北京时间0点分日，两档独立；机构可覆盖额度。额度满429 `ai_quota_exceeded`，details含下一日零点 reset_at；单账号最多两个请求，超出429 `rate_limited`。

为本阶段实际调用模型所需，提供最小超管配置接口：`GET/PUT /api/ops/ai/settings`（只在平台主机上、Access与超管会话双重认证）。PUT使用version、fast_model/deep_model、fast_daily_limit/deep_daily_limit；旧version409。模型名称可配置，服务密钥仅在后端环境变量中设置，不可从机构端或该DTO读取。其余平台后台及页面在阶段7。

报告批量起草尚在阶段6。本阶段实现并测试共用的原子批量预占/逐位结算底层，不提供未实现的报告业务入口。

## 2026-11-15采纳字段核对

用户补丁提交的三个字段与后端兼容，没有新增后端字段要求：

- `applied_suggestion_ids`：方案和内容均放在普通保存请求顶层。保持去重，数组最多30项；新采纳ID须属于本机构且未过期（建议保存7天），此前已保存在文档内的历史ID可保留。编辑已有文档仍须带当前`version`。无效新ID统一404，不把AI调用本身当成业务保存。
- `expected_price_list_rev`：配课建议中的数字`payload.price_list_rev`放在方案PUT顶层；只校验本次新加的行。旧行稳定line_id与原快照保留，新行保留tmp_ ID，保存后用服务器返回的正式文档替换本地。价格变化时409 `price_changed`且不保存，`details`返回最新`price_list_rev`与重算的`computed`。须让顾问确认新价格，再用最新版本提交，不能继续用旧expected值重试。当前补丁该分支只有提示，前端后续可据此完善确认/更新流程；本轮保持附件原样。
- 内容块保存前去掉`basis`是正确做法，仅提交七种块的冻结字段。依据展示仍可用AI响应和专用建议记录，采纳追溯靠`applied_suggestion_ids`。客户端computed、金额和snapshot始终不作为服务器计价依据。

对应真实JSON样例和失败响应继续包含在本包中，接口与v0.3.6一致。
