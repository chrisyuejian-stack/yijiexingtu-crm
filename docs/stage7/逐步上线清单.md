# 艺界星途最终版：逐步上线清单

2026-11-16，冻结接口 v0.3.8，最终数据库 0024。给项目负责人使用，全程可通过本机文件和 Cloudflare 网页操作，不需要终端或编写代码。**交付包已本地构建、模拟验证；没有连接或操作真实 Cloudflare、DeepSeek、线上数据库，没有替您上线。** 下列勾选代表实际操作后再确认，不代表已执行。

## 1. 先确定是哪种环境

- [ ] 记录艺界星途的 Pages 项目名、D1 数据库名/ID、私有媒体桶、私有备份桶和两个域名。不要选原枫琴/渠道 CRM 的资源。域名示例是 edu.yijiexingtu.com 和 ops.yijiexingtu.com，须换成您实际拥有并配置的域名。
- [ ] 首次新建：在自己的 Cloudflare 账号建立独立 Pages Direct Upload 项目、一个 D1、两个关闭公共访问的 R2 桶。全新空库需要 0001–0024 全部迁移。Preview 测试环境另用资源和密钥。
- [ ] 已有艺界星途：沿用它自己的数据库、桶和全部加密/索引/密码密钥。**升级不是换密钥或换空库。** FIELD_KEY、HMAC_KEY、PW_PEPPER、BACKUP_KEY、PLATFORM_PHONE_HMAC_KEY 不变，否则旧数据、密码、索引或备份会失效。
- [ ] 保存当前成功备份、配置和旧部署编号。记录 D1 控制台可用的恢复时间点；可用范围以账号实际显示为准。确认私有媒体桶也保留，数据库备份不包含图片文件本体。
- [ ] 安排停写窗口，通知机构暂不编辑、排课或确认财务；暂停备份 Worker 的两条定时规则。不要让旧 Worker 在新表只执行一半时继续备份。

Cloudflare 控制台进入 D1 SQL Database，选择已核对名称与 ID 的艺界星途数据库，打开 Console。先查看部署记录，再复制 `deployment/final/readonly-checks/01_结构识别.sql` 中的只读语句执行，保存结果。文件内每个完整语句可分别执行。

| --- | --- |
| 阶段4完整 0021 | 0022 → 0023 → 0024 |
| 完整 0022 | 0023 → 0024 |
| 已验收阶段6完整 0023 | **只执行 0024** |
| 完整 0024 | 不再重复迁移 |
| 全新空数据库 | 0001 → 0002 → … → 0024 |
| 不知道版本，或上次中途报错 | 暂停，请后端根据错误与最后成功步骤核对；不猜版本、不删表、不重复从头执行 |

0021 的 plans、0022 的 content_items / ai_requests、0023 的 growth_reports / growth_feedback，以及 lesson_submissions.personal_json、lesson_comments.feedback_versions_json 可辅助识别。0024 的 subject_packs / style_version_meta / style_assets 等也要核对。**看到一个表存在，不代表整份迁移已完成。** 本系统没有用控制台自动替您记录每条手工迁移。

已完整到 0021 及之后时，执行 `02_原业务数量对照.sql`，保存原机构、学员、排课、课时包、财务和方案等数量，升级后再次比较。空库不要先执行这个业务数量查询。

## 3. 通过网页执行需要的迁移

1. 解压“部署资料包”，打开 `deployment/final/离线升级助手/打开升级助手.html`；不要只抽出 HTML，旁边的 JS/CSS 要保留。
若浏览器的单位策略禁止本机HTML，可直接打开 `single-statements/` 下相应版本的编号SQL文本，按顺序复制到D1网页；不用安装工具或改浏览器安全设置。

2. 选择**已经完整完成**的版本，点“生成后续步骤”。默认起点 0023。助手只在本机显示文件，不读取账号、不上传内容、不连接数据库。
3. 点“复制完整 SQL”，到已核对的 D1 Console 粘贴并执行。浏览器限制自动复制时，在已全选的文本框右键复制。
4. Cloudflare 显示本步成功后，才点“云端已成功，记下并进入下一步”。助手中的标记只是您自己的记录，不能代替云端成功结果。定期下载记录并记下数据库 ID。
5. 顺序不可跳过：0022 为 18 个完整语句，0023 为 17 个，**0024 为 114 个**。触发器 BEGIN…END 已保留为一个完整语句，不能自己按分号剪开。若已有 0023，只显示 0024 的 114 步。
6. 任一步报错立即停下，保存错误、当前完整 SQL、最后成功编号、数据库 ID。不要重复点执行、跳过、关外键或添加 IF NOT EXISTS 掩盖状态。由后端核对后继续或恢复升级前备份。
7. 完成后执行 `03_最终对象完整性.sql`：missing_object 无结果；两个旧点评扩展列、subject_pack_versions 的列应存在；quick_check 为 ok；foreign_key_check 无结果。再执行 `04_平台种子核对.sql`：四个学科的 0.1 已发布，四种文档有默认风格，pending_guard_rows 为 0。
8. 再次执行原业务数量对照，与停写前比较；原业务数量应相同。保存所有结果，再发布下节匹配代码。

`deployment/final/migrations/` 是 24 份迁移原件，`single-statements/` 是按完整语句拆分的同一内容，`迁移与步骤清单.json` 附哈希。两种执行方式已在本地验证结构相同。升级助手不做远程执行，也不会自动恢复出错的半迁移。

**数据影响：** 0001–0023 一字未改。0022 新增招生内容与 AI 表，不重算旧方案或财务。0023 新增报告等表、旧点评的可选 JSON 字段，旧记录默认空数组，不重扣课。0024 新增 8 表及索引/触发器，只向新表建立平台版本和稳定 key 映射，不更新原业务行；其中 7 个持久表纳入备份，platform_ops_guards 只是事务检查用临时守卫表。旧 0.1 模板中已修改、不能唯一确认的条目保留原样，并在导入说明中返回警告，不按名字猜归属。

本地演练已验证 0021→0023 原 112 表、98 条样例记录原列原值不变；0023→0024 也逐行核对全部旧表无变化。它们是模拟数据证据，线上实际内容仍要按上面核对。

## 4. 配置绑定、普通变量与 Secret

进入 Pages 项目的 Settings → Bindings，把资源作为**绑定**添加，不是把 ID 写成文本变量。再到 Variables and Secrets，添加普通文本或选择 Encrypt 保存 Secret。保存配置后发布新部署使其生效。详细逐项表见 [Cloudflare配置清单](Cloudflare配置清单.md)，`deployment/resources.template.json` 是无凭据模板。

- [ ] Pages 绑定 CHANNEL_DB、CHANNEL_MEDIA、CHANNEL_BACKUPS，分别指向自己的 D1、私有媒体桶、私有备份桶。
- [ ] Pages 填 TENANT_HOST、CONSOLE_HOST（不同的两个主机名，不带 https 或斜杠），ACCESS_MODE=on、ACCESS_ISSUER、ACCESS_AUD、ACCESS_EMAILS，TURNSTILE_MODE=on、TURNSTILE_SITE_KEY，REFERRALS_MODE=off。
- [ ] Pages 加密保存 FIELD_KEY、BACKUP_KEY、HMAC_KEY、PW_PEPPER、PLATFORM_SETUP_KEY、PLATFORM_PHONE_HMAC_KEY、TURNSTILE_SECRET。已有环境全部保留原值；全新环境可用随包“离线密钥生成器”，每项独立生成并安全保管。Turnstile 的 Secret 从 Cloudflare 获取，不能由生成器代替。
- [ ] 如启用 AI，再加 **DEEPSEEK_API_KEY**，从自己的 DeepSeek 账号取得，仅放 Pages 的 Secret。没有 Secret/模型名时 AI 提示未配置，原 CRM 业务继续使用。
- [ ] fast_model、deep_model 和默认次数在平台已有“AI 模型”页面填写，填账号当前支持的准确模型名；不需要 FAST_MODEL、DEEP_MODEL 等环境变量。不要照抄模拟响应里的 local-demo 模型名。AI_PROVIDER 只是本地测试函数，生产不配置。

0024 平台管理无需新环境变量、新 Secret 或新桶；风格图片沿用 CHANNEL_MEDIA。相对旧 CRM，AI 所需新增项主要是 DEEPSEEK_API_KEY；根手机号索引若先前未配置，仍须 PLATFORM_PHONE_HMAC_KEY。模型和额度存在数据库中。

## 5. 发布 Pages 和备份 Worker

1. Pages 的 Direct Upload 创建新部署，上传本次“Pages正式上传包.zip”。ZIP 根目录直接是 _worker.js、_routes.json、HTML 和 assets 等 **12 个**文件，不要套外层文件夹。**完整源码 ZIP、SQL、日志、离线助手都不上传到 Pages。**
2. 给项目绑定您实际的机构域名和平台域名，与 TENANT_HOST / CONSOLE_HOST 一致；TLS 和 DNS 生效后使用正式域名访问。平台域名设置 Cloudflare Access 应用，只允许授权邮箱，核对 Audience 与签发地址；Access 不替代平台密码和 TOTP。
3. 已有 Git 集成 Pages 项目沿用它的发布渠道，不能直接把现有 Git 项目切换成 Direct Upload；本次 ZIP 是已编译产物。如当前渠道不能上传，先由部署负责人确认项目类型。
4. 在 Cloudflare Workers & Pages 创建或打开独立的艺界星途备份 Worker，通过网页代码编辑器将备份部署包中的 `backup-worker.js` **完整替换**默认代码并 Deploy。文件是单个 ES module，保留末尾 export default。它不是 Pages _worker.js，不能互换。HTTP 访问返回 404 是预期行为。
5. 备份 Worker 同样绑定 CHANNEL_DB、CHANNEL_MEDIA、CHANNEL_BACKUPS，指向与 Pages 一样的三项正式资源；只需配置与 Pages **相同的 BACKUP_KEY Secret**，不需要 DeepSeek、登录或字段加密密钥。
6. 恢复两条 Cron：`0 19 * * *`（UTC 每日19点，即北京时间次日03点启动备份）、`*/5 * * * *`（每5分钟续跑、清理临时媒体/预占）。两条都要有。
7. 先保持停写，完成下一节核心核对。等待/查看实际备份成功日志后再结束停写；不要把“Worker已部署”当作“备份已成功”。

备份是加密数据库快照，包含新平台版本、机构映射、图片的 R2 key 和 hash。**不会把媒体桶里的图片本体复制到备份桶。** 原 CHANNEL_MEDIA 必须保留，必要时单独由负责人安排媒体备份；不要删除桶或改变对象键。

## 6. 上线后逐项验证

- [ ] 无痕打开机构域名根地址，登录单机构账号和多机构账号，检查返回 api_base；机构路径和根登录都可用，其他机构内容不可读。
- [ ] 打开平台域名，先过 Access。首次空环境点“首次部署：初始化超管”，输入 PLATFORM_SETUP_KEY，按页面生成的绑定密钥在手机验证器保存，再设用户名/密码及动态口令；完成后等下一个动态口令登录。已有超管环境不再次初始化。
- [ ] 用自己的测试机构核对学员、排课、课时包、收支和统计报表，打开旧方案与其已发送版本，确认文字、价格与数量保持原样。到期/停用后业务403、公开入口404；恢复后未过期会话仍可用。
- [ ] 用测试机构确认反馈、家长绑定、成长报告发布/撤回、家长时间线；旧纯文字点评可显示，不增加老师照片上传权限。
- [ ] 在新平台页面接入后验证：模板新建草稿→保存→预览内容→发布→测试机构显式导入；二次导入不改原价格或名称。新版本不自动覆盖已有机构。平台新模板包/风格包 UI 由前端方完成，本包提供接口和真实示例，不宣称已提供新管理页面。
- [ ] 风格上传示例 ZIP，预览应明确是“平台示例”；发布到测试机构，检查指定范围可见、其他机构不可见；四种文档默认包分别设置。旧已发送/发布内容继续引用旧版本。示例图只有1像素，会提示清晰度警告，只供流程验证。
- [ ] 家长/公开分享可读授权图片；撤回报告、取消分享或解除绑定后按规则失效。私有图片 URL 不应成为任意公开资源入口。
- [ ] 前端预览/导出接好 asset_base，并在实际机构主色、实际照片背景上做对比度检查和安全文字面板。服务端上传仅检查固定颜色对比度，不代表实际页面已经视觉验收。
- [ ] 配好真实模型后，由您在测试机构发起一次 AI 请求，确认建议先展示、采用后普通保存才写业务；检查机构额度、平台 day/tenant/tool 统计和禁用词。不要把本地模拟通过等同于真实模型质量/成本已验收。
- [ ] 在平台备份页或 `readonly-checks/05_最近备份.sql` 查到新版本成功记录，并到私有备份桶核对同一备份目录的 manifest.enc；0024 新表在新完整备份中。记录成功时间和目录。
- [ ] 保存部署编号、0024完成记录、配置项清单（不公开Secret）、检查结果；通过后结束停写，保留旧部署和恢复资料。

如核对失败，保持停写，保留错误和时间点，由负责人判断回滚部署或恢复数据库。0024 没有向下迁移脚本，不自行删表。数据库恢复会影响恢复点之后写入，因此须先停止写入再由负责人处理。
