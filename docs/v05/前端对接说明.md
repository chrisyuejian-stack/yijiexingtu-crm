# v0.5 后端对接说明

2026-11-17。前端由 Claude 实现；本轮没有改动 src/tenant、src/console、src/ui 或分享页。实现依据为本目录冻结版契约（原草案 v0.1 + 用户确认的 price_tbd）。

## 联调材料与路径

[actual/本地真实请求响应.json](actual/本地真实请求响应.json) 包含 **39 组实际执行的本地 HTTP 请求与响应**，不是人工推演：内存 D1、模拟 R2、AI_PROVIDER 模拟模型；姓名、内容、ID、分享令牌均为本地合成数据。未调用 DeepSeek 或 Cloudflare。重新采集脚本为 scripts/v05-capture.mjs，供开发者使用。下文序号对应 JSON 的 examples 数组顺序（从 1 开始）。旧 examples/ 是文档阶段人工样例，以 actual/ 的真实结构和冻结契约为当前依据。

员工请求始终使用登录返回的 api_base：根会话 `/api`，路径会话 `/{slug}/api`。写入带现有会话、同源 Origin、application/json；AI 另带 Idempotency-Key。新 DTO 不返回 tenant_id，不能在请求里指定机构。错误沿用 `{error,message,details?}`，成功响应顶层 warnings 为字符串数组；checks.warnings 仍是检查项对象数组。

## 编辑、转换和报价

- `GET /plans/{id}`：例 1、6。员工读模型为 doc_version=2，stored_doc_version 区分实际存储格式，converted_from=1 表示本次内存转换；GET 不改库。旧发送/签约修订和旧分享仍保持 v1，应保留 v1 渲染分支。
- `POST /plans`：例 3、27。输入 `{doc,expected_price_list_rev?}`，来源仍遵守学员/线索/意向三选一。创建返回 id_map。
- `PUT /plans/{id}`：例 2、8、30。输入 `{version,doc,expected_price_list_rev?,date_shift?,applied_suggestion_ids?,applied_cards?}`。**不要把整个 GET 响应放进 doc 或展开成请求。** doc 只取业务字段 doc_version/student_id/source_lead_id/subject/title/style/meta/module_order/modules；computed 和历史 applied_suggestion_ids 如回传也不作为可信输入。brief/reference/manifest/party/id/version 等编辑元信息不属于 doc。需要完整私有编辑状态时再 GET。
- v2 的 PUT doc 是完整文档替换，须有全部 11 模块；各集合使用稳定 ID。新增元素给全篇唯一 tmp_ ID，成功后按 id_map 替换元素及关联，不靠数组下标定位。
- 旧 v1 仅 GET 不升级；确认保存 v2 才建转换记录。转换失败返回 422 legacy_conversion_failed，不能悄悄清空旧课表再保存。历史修订字节不变，旧发送链接仍指向原修订。
- `POST /plans/{id}/quote-preview`：例 9，只预览。变动后要重新报价，不能使用 AI 全组 computed 冒充只采用部分卡后的结果。新增 catalog 行须提交当前 expected_price_list_rev；旧行沿用锁定快照。例 26 是真实 409 price_changed，details 含 price_list_rev 和新 computed；顾问确认后用最新修订重试，取消不保存。
- catalog/manual 来源须显式区分；变更已有行来源或 course_id 须删除后新增。catalog 价格取服务器快照；manual 单价是顾问明确输入。manual 行不能 reprice，整体换库价仍用原 reprice 流程。
- 库课目录没有统一的“默认频率”字段，后端不推测每周频率；课程行 frequency_text 由顾问或合规 AI 建议填写。minutes 可从报价课程带入。

### 价格另议和分期

例 3、10–14 展示“已确定 400 元 + 另议项”的真实流转。price_tbd 默认 false；**true 且 manual_unit_price=null 才是活动另议**。模型不会自动勾选另议。已填确定价则按确定价计算。

- 普通未填价、price_tbd=false：可存草稿，不能发送/导出。
- 活动另议、整阶段 pending：允许发送/导出，总额未知时 amount=null，显示已确定部分 known_amount + 另议/待定项，不能显示为零元或最终应付。pending 阶段的草案课和 draft_amount 不对外返回。
- 可选课不计入总价/分期；可选课存在活动另议时 has_tbd 仍为 true，因此也不能签约。不要只看 amount 是否非 null 判断能否签约。
- 发送/导出有 manual 行时需 acknowledgements.manual_pricing=true；签约须 complete=true、has_tbd=false、installment_status=balanced，并校验实际已发送修订。修改工作稿不改变已发送版本。
- 费用支持阶段附加/其他费用、固定或比例减免，分期 per_stage/custom/fixed；整数分由服务器分配。总价未知时不伪造优惠后的最终总价或分期余额。

### 日期平移

`POST /plans/{id}/shift-dates/preview` 输入 `{version,months}`，例 7；返回 doc/computed/save_options。顾问确认后把返回 doc 与 save_options 原样放入普通 PUT（例 8），不要再次平移。日期移动不改课时、数量、价格和正文内日期；月底夹到目标月末，旧日级范围通过只读 legacy_range 保留。文本日期提醒由顶层 warnings 给出。

## 私有原文、参考与相似检索

- `GET/PUT /plans/{id}/brief`：例 4、5、28；PUT 输入 `{version,text}`，首次 version=0，清空用 text=""，响应 `{brief,warnings}`。brief.version 独立，不让 plans.version 增长。409 version_conflict 的 details.latest 是当前 brief。原文单独字段加密，不进入 CRM 备注、业务修订、模板、分享或检索摘要。
- 仅有 plans.write 的员工可读写 brief（默认主管/教务/顾问）；财务及家长不返回该字段，直接访问也拒绝。复制方案不复制原文。签约/归档方案不能修改原文。
- `PUT /plans/{id}/reference`：例 15；输入 `{version,reference_version,enabled,revision_id?}`。首次 reference_version=0，固定某个本机构修订，不随工作稿更新。其版本独立于方案。
- `GET /plans?reference=true/false`：例 16。新权限点 plan_templates.read/write、plan_references.write 已进入 me.capabilities，沿用 plans 功能模块，不新增收费开关。财务无模板和参考修改权限。
- 相似检索为服务器内部能力：最多 5 个，只取本机构固定签约修订、明确参考修订和本机构模板。仅发送去身份的结构摘要，界面不显示“参考 N 份”、原方案 ID、相似名单或审计元数据。

## 模板库与平台样例

例 17–25 覆盖机构模板全流程；例 35–39 覆盖平台样例发布、导入映射与只读读取。

| 接口 | 请求关键字段 | 返回 |
|---|---|---|
| POST /plans/{id}/template-preview | version、revision_id?、keep_teacher_photos? | doc/redactions/checks/warnings；预览不保存 |
| POST /plan-templates | name/description/applicability/source/doc | 201 template/warnings；再次校验脱敏与机构归属 |
| GET /plan-templates | origin/subject/q/offset/limit | items/total/next_offset/warnings；摘要无 doc |
| GET /plan-templates/{id} | 无 | template/warnings；含 doc |
| PUT /plan-templates/{id} | version/name/description/applicability/doc | template/warnings；409 带当前完整 template |
| DELETE /plan-templates/{id} | version | ok/warnings；不删已创建方案 |
| POST /plan-templates/{id}/instantiate-preview | version/shift_months/pricing:"current" | doc/computed/price_list_rev/checks/warnings |
| POST /plans | doc/template:{id,version,shift_months,pricing:"current"}/expected_price_list_rev | 创建实例；不复制原文和历史 |

脱敏预览仍需顾问确认，不把预览当成已保存模板。模板清除姓名、年级、绑定、顾问和个人图片等；保存接口再次检查联系方式和已知姓名。实例化用现价、重新分配所有结构 ID。已停用/缺报价/缺引用的 catalog 行保留待处理并给 checks，不能静默变为自由课程。

平台用原 `/api/ops/subject-packs` 整包创建与发布接口；新增 content.sample_plans，每学科最多 2 个。结构见冻结契约及 schemas/platform-sample.schema.json、例 35 的完整包输入。stable key 是可移植结构，不提交机构 ID、报价、快照或图库 ID；元素 key 不能重复，引用须在本包/本样例中有效。版本整数与 pack_version 分开。机构显式导入时事务映射 key→本机构 ID，已有课程不被覆盖。平台模板 id 是 opaque 字符串，URL 路径需 encodeURIComponent；不要自己拆 ID 猜库表。平台模板 readonly，修改返回 403 readonly_template；可另存为本机构模板。

风格包只新增可选组件 `plan.timeline: list/rail`、`plan.goals: list/cards`、`plan.photos: grid_2x3/grid_3x3`。旧包没有这些键时由前端采用默认布局，不要求重发旧包。资源继续通过授权 asset_base 加载。

## 长输入 AI 与逐卡采用

例 28–31 展示保存原文→单次 AI→采用→用量。`POST /ai/plan/brief` 输入 `{plan_id,doc_version:2,plan_version,brief_version,scope:"auto"或模块key,instruction?,tier:"fast"或"deep"}`，带 Idempotency-Key。服务器只读取已保存原文；保存原文失败/版本冲突先处理，不能假装模型使用的是未提交文字。

原 fill-from-consult/stage-courses/polish/adjust 路径继续保留；请求指定 doc_version=2 时走同一 `plan.v2.cardset` 协议，未指定的旧协议继续兼容尚未转换的 v1。当前存储已是 v2 却调用旧协议，返回 409 doc_version_conflict。

- 成功返回 `{suggestions,warnings,usage}`。每组 payload 包括 intent/variant/recommended/cards/completion/computed/price_list_rev。卡有稳定 entity_id、parent_id、field、服务器 before、after、evidence、depends_on、default_selected，详见冻结白名单；不执行任意 JSON path。
- 一次 brief 模型调用可同时返回文字、阶段和课程卡；fast 120 秒、deep 150 秒，共用硬截止。内部解析重试不增加次数或延长截止。合规空建议 200 计 1 次；错误/超时 502 不计，超时 error=ai_timeout。
- 价格/快照/computed/price_tbd 不采信模型；旧行按原快照，新 catalog 行按现价，新 manual 单价为空。AI 只提建议，业务零写入。测评分数不能推断；未验证的文字标 inference，不自动选中。
- 顾问可选择卡、取消、改后采用。先在本地文档应用卡，部分采用后调 quote-preview，再普通 PUT；applied_cards 为 `[{suggestion_id,card_ids,edited_card_ids}]`。新增阶段的课程/分组要一起选依赖卡，或手动调整并声明 edited_card_ids。采用互斥配课组只能选一组。
- 方案 version 变化后旧卡不能套用；生成新建议或人工编辑。server before 不是模型伪造值。建议记录与业务保存为不同事务，AI 成功不等于方案已保存。
- 幂等重放在原文/工作稿变动后仍返回原建议顺序、usage、warnings，不重新调模型、不扣次；新意图使用新键。沿用 10 分钟快速响应、至少 2 天重放凭据和 7 天建议记录。

## 公众号正文

例 32–34。content 增加 `text_format:"plain"/"inline_v1"`。旧缺失字段视为 plain，原字符串不解析、不读时迁移。新编辑器显式提交 inline_v1。

inline_v1 只支持同一段落内 `**加粗**`、`*斜体*`、`==高亮==`、`[[品牌强调]]` 与反斜杠转义，不存 HTML。正文/列表/表格/引用/图片说明可使用；标题和 article 元信息保持纯文字。不完整、空、交叉/嵌套/跨段格式整段降为普通文字，200 保存并 warnings 提醒。禁词与事实检查针对可见文字，plain_span 是 Unicode 码点偏移，不是 UTF-16 下标。AI 起草/改写保留格式；article 的人工栏目/头图/作者/日期/页脚不由模型改写。

前端负责安全渲染 token、工具条、撤销/重做和样式预览；不要使用任意 HTML 或把标记变成可执行 Markdown。当前旧前端未实现这些 v0.5 交互。
