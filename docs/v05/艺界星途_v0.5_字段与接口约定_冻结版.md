版本：冻结 v0.1 + price_tbd 补充 · 2026-11-17。状态：**用户已确认，作为实现依据**。

冻结说明：用户确认原草案 §16.2、§16.3 与 v2 长动作 120/150 秒，§16.1 按本文 price_tbd 增补执行。原草案归档保留；本冻结版优先。

本文以 v0.4.1 完整源码合入《最终前端_给GPT_20261117》后的版本为基准，按最新设计稿（含第 8、9 节）及用户确认冻结。后端实现与验证见本目录交付说明；Claude 负责 v0.5 前端。examples 中保留的是人工构造的原契约样例；actual/ 是实现后实际执行的本地模拟 HTTP 请求响应，两者均不是线上数据。

## 0. 适用范围与兼容边界

1. 新方案及编辑器读模型采用 `doc_version: 2`；原 CRM、课后反馈、成长报告、账号、财务统计接口不变。
2. `plans` 表不改结构；0001–0027 原样保留。v2 写入现有 `doc_json`。模板、参考标记和员工原文使用新增附属表，本轮新增迁移为 0028_plan_v2.sql，只增加附属表、索引和保护触发器。
3. 机构 ID 只取会话；新 SQL 只在 repo，按 `tenant_id` 限制。主资源读取/修改的跨机构与不存在均 404；文档内图库引用按既有规则，对不存在/不属本机构统一 422 invalid_image，不区分原因。新增 DTO 不含 `tenant_id`。根会话用 `/api`，机构会话用 `/{slug}/api`，前端始终取登录的 `api_base`。
4. AI 只写建议、计次和既有审计，不写方案、CRM 备注、模板或价格表。服务器计算金额；客户端伪造的 `computed`、库课程快照和派生小计一律忽略。**人手输入的自由课程单价是明确的业务输入，不是可信计算结果**，详见 §4。
5. 现有方案状态 draft / sent / signed / archived、发送修订、签约修订、分享令牌、家长关联、机构状态与会话规则不变。signed / archived 不可编辑，复制后再改；sent 的工作稿可修改，但旧分享指向旧发送修订。
6. 公共分享继续 `/s/{token}` + `/api/share/{token}`，不登录、不进 CRM；只读已发送修订，保留 noindex、no-referrer、CSP 和失效统一 404。不能因编辑器转换而改变旧链接。
7. 所有新增/扩展成功 JSON 顶层包含 `warnings:string[]`（无提醒为 []）；checks.warnings 仍是原检查项对象数组，不与顶层混用。沿用错误形状 `{error,message,details?}`。写请求使用 application/json、同源 Origin 和现有会话 Cookie；以下例子省略 Cookie/Origin，不代表可以匿名写入。AI 沿用 usage 和建议重放机制。分页仍为 offset / limit / next_offset。
8. 这是 v0.5 的**已确认增量契约**，旧 v0.3.8 或 v0.4.1 不支持这些字段。v0.5 前后端应配套上线；不把 v2 响应直接投给现有 v0.4.1 方案编辑器。旧用例若必须改变预期，实施前另列最小 diff，不擅自修改或跳过。

## 1. 公共类型和写入约定

| 类型 | 定义 |
|---|---|
| Text(n) | 普通字符串，最多 n 个 Unicode 码点；不接受 HTML。除正文外去首尾空白。正文统一 CRLF→LF，不改段内空格 |
| Date / Month | 真实日历日期 YYYY-MM-DD / 月份 YYYY-MM；2000–2100 年；空值用 null，不用空字符串 |
| Money | 人民币元，JSON number，非负、最多两位小数，单项不超过 100000000；入库先转整数分，计算不使用浮点乘加 |
| Quantity | >0、最多两位小数、≤1000000；草稿未填可为 null；不能把 null 当 0 |
| Stable ID | 新元素以 `tmp_` 开头，保存时服务端生成稳定 ID 并返回 id_map。全篇临时 ID 唯一。已有稳定 ID 必须属于本方案；不能借用别的方案元素 |
| version | 正整数，乐观锁。与 doc_version、模板发布版本、brief.version 均不是同一个概念 |
| 可选字段 | PUT doc v2 是完整业务文档替换；缺可选字段按表中默认，缺 11 模块或必需结构 422。旧 v1 保存的局部合并兼容仅适用于尚未转换的 v1，不套到 v2 |

单个 v2 写入 JSON 上限 1 MiB（超限 413 `payload_too_large`）；AI 输出沿用现有 250000 字节上限。结构上限是接口约束，不在界面展示技术细节。所有读响应中的只读字段可回传，但由服务器重建或忽略，不允许据此越权。

## 2. 文档总表

编辑器 `GET /plans/{id}` 继续使用**展开的文档 + 元信息**，不增加 `data` 外壳。写入使用 `{version, doc, expected_price_list_rev?, applied_suggestion_ids?, applied_cards?, date_shift?}`。

| 路径 | 类型/默认 | 说明 |
|---|---|---|
| doc_version | integer=2 | v2 必填；旧数据缺失视为 v1 |
| student_id / source_lead_id | string/null | 原 v0.4.1 来源绑定；不由基本信息的手填姓名改写。prospect 沿用原有创建和转学员接口 |
| subject | 原开放学科 key | 如 music_interest；不是自由方向字段，沿用机构开放范围 |
| title | Text(200) | 方案标题，允许空字符串；空时列表显示“未命名方案”。不是课程名 |
| style | 原 style 对象 | pack_id/pack_version/cover_image_id/text_mode/text_mode_resolved/focal_point/show_unit_price/show_latin_eyebrow/show_consultant；原默认和授权继续有效 |
| meta | object | start_month、target、consultant_id、budget_cap 保留旧含义；另增 budget，见下表 |
| module_order | 11 个唯一模块 key | basic, assessment, strategy, path, timeline, courses, teachers, fees, goals, photos, about；必须恰好包含全部，不以数组下标做元素引用 |
| modules | 11 个完整对象 | 每个都有 visible:boolean，默认 true，about 默认为 false；隐藏不删除内容、不改变课程计价 |
| computed | 只读 | 服务端结果，详见 §4.6。客户端提交的值不采用 |
| applied_suggestion_ids | string[]，只读历史 | 原采用记录；本次新增采用在请求顶层传入，至多 30 个 |
| id/version/status/current_revision_id/sent_revision_id/signed_revision_id/updated_at/updated_by/party/party_name | 只读 | 原元信息语义不变 |
| reference | 有编辑权时只读 | `{enabled,version,revision_id,updated_at}`；未标记 false/0/null/null；财务只读不返回 |
| stored_doc_version | 只读 1/2 | 数据库当前工作稿实际格式；GET 内存投影不写库 |
| converted_from | 只读 1/null | 本次响应是否由 v1 转换；不会显示给家长 |
| brief | 员工专有只读摘要 | 有 plans.write 时为 `{version,text,updated_at}`；其他访问完全不返回此键。全文独立保存，见 §8 |

`meta`：

| 字段 | 定义 |
|---|---|
| start_month | Month，默认方案日期所在月；旧字段兼容，不替代路径中的实际起止月 |
| target | `{node_key:string/null,month:Month/null,text:Text(1000)}`；保留旧锚点，无输入默认 null/null/空字符串 |
| consultant_id | string/null；原负责顾问，必须是本机构账号，不能由显示姓名反推 |
| budget_cap | Money/null；**沿用原“整个方案预算上限”**，用于原 over_budget 检查，不能把“一年三万”直接存成此字段 |
| budget | `{amount:Money/null,period:"total"/"year"/"month"/"unspecified",note:Text(500)}`；默认 null/unspecified/空。amount 与 period 是明示的人手输入或带可验证原话的建议；推断不自动采用 |

`budget_cap` 与 `budget` 可同时存在，但不能数值冲突：period=total 且两者均非 null 时须相等。只有 budget 的 total 会派生同额 cap；年/月只做说明和相应周期对比，不换成总额上限。见 §4.7。

### 2.1 模块共同字段

11 个模块的 visible 默认如上。assessment / strategy / path / timeline / courses / teachers / fees / goals 增加 `title: Text(80)`，默认为下表中文标题，空标题允许；basic / photos / about 的模块名固定，照片页仍可各自命名。标题仅改变展示，不改变 key、权限或 AI 范围。

### 2.2 basic：基本信息

| 字段 | 类型/默认 |
|---|---|
| student_name | Text(100)，空 | 从绑定对象一键带入后可改，**不更新 CRM 学员姓名** |
| grade | Text(100)，空 | 自由填写，不校验学校年级枚举 |
| plan_date | Date/null，创建时本机构北京时间当天 |
| direction / direction_en | Text(200)，空 |
| english_enabled | boolean，false；只控制方向、课程、目标中的英文字段展示，关闭不清空英文内容 |
| cover_visible | boolean，true；basic.visible=false 时基本信息和封面都不显示 |
| cover_eyebrow / cover_subtitle | Text(200) / Text(1000)，空；承接旧 cover 文案 |

公开展示继续执行既有家长同意/昵称规则；绑定学员的 basic.student_name 不是跳过同意的途径。员工导出、家长查看与公开分享按既有授权渠道处理。纯意向来源仍按原 prospect 公开脱敏规则，不公开联系人、电话等。

### 2.3 assessment：学员测评

默认标题“学员测评”。`text: Text(12000)`，保留换行，支持 `**加粗**` 和行首 `- ` 列表；只渲染这两个能力，不执行任意 Markdown/HTML。`scores` 最多 20 项：`{id,label:Text(50),value:number|null,max:number}`，max 为 1–100 的有限数，value 为 0–max 或 null，人工输入或明确引用，不推断打分。`tags: Text(50)[]` 最多 30 个。不强制任何测评维度，不自动改 CRM 评分。

### 2.4 strategy：学习/申请策略

默认标题“学习 / 申请策略”。`text: Text(12000)`，与 assessment 相同的有限加粗/列表，不含 HTML。

### 2.5 path：学习路径

默认标题“学习路径”。`stages` 最多 100 项，按数组顺序显示。

| 阶段字段 | 类型/默认 | 约束 |
|---|---|---|
| key | Stable ID，原 stk_ 保留 | 被课程、附加费、分期引用 |
| name | Text(100)，空 | 自由命名 |
| stage_type_id | string/null，null | 一键带入可选；非空必须本机构有效阶段类型。旧已停用引用保留快照 |
| start_month/end_month | Month/null | 都有时 end≥start。v2 不强制连续，不禁止跨阶段重叠；重叠作为提醒，不阻断保存 |
| teaching_weeks/weeks_note | integer 1–10000/null + Text(1000) | 沿用原手填周数说明规则；均空合法 |
| goals | Text(1000)[]，最多 30 | 给家长看的目标；顾问提醒不得混入 |
| nodes | 最多 50 项 | `{id,date:Date|null,name:Text(200),note:Text(1000)}`；属于当前阶段 |
| node_tags | Text(100)[]，最多 30 | 保留旧标签 |
| stage_snapshot | 只读 object/null | 系统阶段带入时保留旧快照；自由阶段为 null |

阶段时长 `computed.stages[].months` 为首尾月都计入的月数；任一月空则为 null。**旧日级 start/end 不丢失**：转换时只读 `legacy_range:{start:Date,end:Date}|null` 保留原日范围（客户端直接传值不能改写）；未改该阶段月份时继续据此算周数，手工改月份/平移日期后由服务器生成新月首/月末范围。不能把旧“11 月 17 日”默默改成“11 月 1 日”。

### 2.6 timeline：关键节点时间线

默认标题“关键节点时间线”。`items` 最多 200：`{id,date:Date|null,name:Text(200),type,note:Text(2000),source_key:string|null}`。type 仅 `grade_exam/competition/art_exam/application_deadline/performance/other`；未知用 other，而不是猜一个考试类型。source_key 为可选的机构日历稳定 key，一键带入后仍可自由改日期和文字，不改日历。考级、比赛用本模块，不另建两套规划表。

### 2.7 courses：课程计划

默认标题“课程计划”。仍以平面 `lines` 保存，避免同一课程既在组内又在顶层出现两份；新增 `stage_settings` 和 `groups` 描述分组。UI 按 path.stages 顺序→groups 顺序→lines 顺序展示。

| 集合 | 字段 |
|---|---|
| stage_settings | 最多 100 项：`{stage_key,pending:boolean,pending_note:Text(2000)}`，stage_key 唯一。未出现的阶段按 false/空；pending=true 时可存原课程，但它们不作为确定报价，见 §4.6 |
| groups | 最多 200 项：`{id,stage_key:string|null,name:Text(100)}`；stage_key=null 为“未分阶段”。同名组允许，id 不重复 |
| lines | 最多 300 项，见下表 |

| 课程行字段 | 定义 |
|---|---|
| line_id | Stable ID，沿用 ln_；一个已有库课程行不能换 course_id，须删后新增 |
| stage_key / group_id | 本方案稳定 ID 或 null；非空引用须存在、组所属阶段须匹配。允许未分阶段行，不假造阶段 |
| pricing_source | `catalog/manual`；已有 catalog 行不允许在同一 ID 下变 manual，改为新行 |
| course_id | catalog 必填本机构课程 ID；manual 为 null。manual 如从库改价可填写 `origin_course_id`，只作关联，不取得库价身份 |
| name / name_en | Text(200)，空；库课程首次由服务器带入，后续展示名可自由改，不改变报价来源或旧快照 |
| frequency_text | Text(500)，空；不从这句话反推数量 |
| minutes | integer 1–1440/null，null |
| billing_mode | `per_unit/per_term/per_semester/per_month/package`，manual 默认 per_unit，catalog 由服务端快照确定；保持旧 5 种方式，不将包价误变成课时价 |
| qty | 与 billing_mode 唯一对应的 `{units/terms/semesters/months/packages: Quantity|null}` |
| teaching_units | Quantity/null；per_unit 及 package 服务端派生，其他方式可人手补充，否则总课时只统计已知部分 |
| price_tbd | boolean，默认 false，仅 manual。true 且单价为 null 表示“价格另议”，允许发送/导出，对外显示“另议”；单价已填时按已知价计算，不计入活动另议项。catalog 固定 false |
| manual_unit_price | Money/null，**仅 manual 人手输入**；catalog 忽略并提醒。AI 提议自由课程时为 null，不从模型取金额 |
| units_per_package | integer 1–100000/null；仅 manual package 必填；catalog 用原快照，沿用原整数每包课时；package 与教学课时按同一规则折算 |
| optional | boolean，false；catalog 从原 snapshot.optional 投影，忽略客户端改写；manual 可人手设置。optional 行不计总额和分期 |
| note | Text(2000)，空 |
| includes | 原最多 50 项 `{label,form,schedule_text,duration_text}`，字段长度沿用原实现 |
| ai_filled | boolean，false，仅来源标记，不是报价授权 |
| snapshot | 只读；旧完整快照逐值保留（包括 pricing.amount_cents、mode、course_version、price_list_rev、taken_at）；新 catalog 行只由服务器建立。manual 建服务端价格快照，source=manual，不伪造 course_version |

所有 manual 行展示“非价目表”。保存普通业务文档不能顺手修改机构课程或价目表。

### 2.8 teachers：师资

默认标题“师资”。`groups` 最多 30 项：`{id,role:Text(100),members:[...]}`，合计最多 60 人。每人：`{id,teacher_id:string|null,name:Text(100),title:Text(200),introduction:Text(12000),photo_image_id:string|null,proposed:boolean}`。proposed 默认 false。系统老师可一键带入姓名/介绍，之后是方案自己的文案；teacher_id 非空必须本机构，旧已停用老师可保留已有快照。teacher_id=null 的自由老师同样可保存；不创建 CRM 老师账户。照片必须是本机构图库，可见渠道按既有同意规则检查。

### 2.9 fees：费用与缴费

默认标题“费用与缴费”。为保证旧转换无损，**原字段 visible/installments/custom/due_dates/note 的值全部保留**，只新增 title/stage_extras/other_fees/discount/fixed。

| 字段 | 定义 |
|---|---|
| stage_extras | 最多 100 项 `{id,stage_key,label:Text(100),amount:Money|null,note:Text(1000)}`，非空 stage_key 必须本方案阶段 |
| other_fees | 最多 100 项 `{id,label:Text(100),amount:Money|null,note:Text(1000)}` |
| discount | `{type:"none"/"fixed"/"percent",amount:Money|null,rate_bps:integer|null,note:Text(1000)}`；默认 none/null/null/空。fixed 仅填 amount；percent 仅填 rate_bps（1–10000，表示**减免比例**），none 两者 null |
| installments | 保留 `per_stage/custom`，**拟新增 `fixed`** 支持设计稿直接填金额；旧 v1 仍仅两种 |
| custom | 原 ratio_bps 项数组（stage_key、label≤30、due、ratio_bps），合计 10000，只有 custom 模式可非空 |
| due_dates | 原 `{stage_key:Date|null}`，per_stage 使用；custom/fixed 模式仍可保留但不参与计算 |
| fixed | 最多 100 项 `{id,stage_key:string|null,label:Text(100),due:Date|null,amount:Money|null}`；只有 fixed 模式可非空 |
| note | 原 Text(3000) |

优惠超出应付、分期合计不符可以存为未完成草稿，计算输出明确提醒，不偷偷修金额；发送/签约/导出规则见 §4.8。新增 fixed 模式与待报价流转属于 §16 待确认的产品边界。

### 2.10 goals：目标院校/目标

默认标题“目标院校 / 目标”。`groups` 最多 30：`{id,title:Text(100),items:[...]}`，每组最多 100 项：`{id,name:Text(200),name_en:Text(200),tier:Text(50),note:Text(2000)}`。tier 可为“冲刺/主申/保底”或任意短文字，不要求院校库 ID；本轮不新增院校真实性数据库。

### 2.11 photos：附加照片页

`pages` 最多 20：`{id,title:Text(100),layout:"grid_2x3"/"grid_3x3",image_ids:string[]}`。每页 1–8 张、页内不重复；空 pages 允许。全部图片均须本机构图库。2×3 超过六张时由前端继续分页，不能裁掉第七、八张；不保存 base64 或远程 URL。失效/无授权图片不得进入公开快照。

### 2.12 about：机构介绍

沿用现有 `visible` 和 `image_ids`（最多 50）；新增可自由填写的 `text:Text(12000)|null`。null 表示使用当前方案的机构档案快照，空字符串表示刻意留空；不修改 settings/profile。标题、地址、品牌和二维码仍按原 context/style 渲染，不处理已记录的 qr_image_id 与 consultant_qr 统一待办。

## 3. v1 → v2：确定转换、无损核对和历史保护

### 3.1 逐字段映射

| v1 路径 | v2 处理 |
|---|---|
| doc_version 缺失 | 仅编辑读模型补 2，stored_doc_version=1，converted_from=1 |

### 3.2 可逆检查的具体含义

- **GET 不写任何表，不新建修订，不改变版本**。转换函数产生 v2 投影和服务端内部“转换清单”，不向客户端暴露私密原件。
- 完整原件已经存在不可变 `plan_revisions.doc_json/context/manifest` 中。首次保存 v2 时在新增的转换记录中保存 `source_revision_id + source_doc_sha256 + mapping_version + v2_initial_projection_sha256`，必要的未覆盖字段存在只供后台核验的 conversion 元数据。原修订不改。
- 逆向核验针对“刚转换、尚未人工改动”的投影：按确定映射回填原结构，与原 JSON 做规范化逐字段深等、原 context/manifest 哈希一致；课程原快照、五种 qty、optional、includes、分期和 computed 金额必须完全相等。只对对象键顺序做规范化，不折叠空格/列表顺序。
- 如果不能无损核验，编辑器 GET 返回 422 `legacy_conversion_failed`，不落库、不新报价；家长/旧分享仍可按 v1 看原修订。此错误记录可定位的内部原因，机构端提示“原方案需要检查，请联系管理员”。不得回退成丢字段转换。
- 已修改后的 v2 不能声称可无损逆成 v1；“恢复历史”是取原不可变修订建立新工作修订，保留旧审计，不是覆盖历史或降级改写旧分享。
- 首次 v2 保存沿用当前 version 乐观锁，在一个事务内保存新工作稿/新修订/转换记录。并发失败 409，不能出现只转了 doc 而关联没转的半成品。若源工作稿与 current_revision 不一致，先阻断核对，不用近似修订做原件。

### 3.3 旧修订、签约和分享

`GET /plans/{id}` 给员工转换后的编辑投影，即便已签约也只是只读投影。`GET /plans/{id}/revisions` 及选定版本的 export / parent / share 按**那份修订自身 doc_version** 渲染，v1 保持原结构。签约只锁选定的已发送修订。旧 token、有效期、撤销、媒体授权均不变。新 v2 发送时固定 v2 文档和 context/manifest；只读渠道不能拿当前库老师/价格覆盖快照。

## 4. 计价、预算、待报价与日期

### 4.1 价目表行

已有 line_id 使用原价格快照，课程停用/改价不使旧报价漂移；新增库行使用当前价目表，active/定价/归属检查沿用原规则。整体换价仍走现有 reprice。reprice 只适用于 catalog；manual 不混入选中换价，传入 manual 行返回 422 `validation_failed`，说明需手工改价。

新 catalog 行、模板实例化取当前库价、AI 采用新行，保存携带 `expected_price_list_rev`。缺少该字段且存在新增 catalog 行时 422；与当前不一致 409 `price_changed`，`details:{price_list_rev,computed}`，其中 computed 是**整份最新试算**。旧额取前端当前 doc.computed.total.amount，新额取 details.computed.total.amount；基线没有 computed.old/new 两层，不能自行改成该形状。确认后用最新 rev **重算并再次提交**；不是确认后永久锁价。旧行仍使用旧快照，不整体重报价。

### 4.2 自由课程

人手输入 manual_unit_price × 对应 qty，按现有 centsProduct 的“整数分乘百分位数量、半分向上”规则。例：300.01 × 1.50 = 450.02 元。per_term/per_semester/per_month 不从频率猜课时；package 还要 units_per_package。snapshot、line_total 或模型产出的金额不能覆盖该算法。manual 单价可为 null（待报价），0 是明确免费，与 null 不同。

### 4.3 汇总

1. 逐行算整数分。optional 行列入 optional_fees，不进总额和分期。hidden 只影响展示；隐藏 courses/fees 不等于免费。
2. 阶段额 = 该阶段非 optional 课程 + 该阶段附加费。未分阶段课程独立列入 unassigned，不造一段虚假学习路径。
3. subtotal = 各确定阶段额 + 未分阶段额 + other_fees；可选费用不进 subtotal。
4. 优惠 fixed 直接减整数分；percent 按 subtotal × rate_bps / 10000，半分向上，最终 total=subtotal−discount。超额优惠不裁为 0，标记 discount_invalid，total.amount=null。
5. 不完整课程、待定阶段或附加费 amount=null 使完整 total.amount=null；同时提供 known_amount。不能向家长显示“总价 0 元”掩盖未知费用。沿用原服务端金额上限，确定行/总额超过 100000000 元时 422，不能因拆成多项绕过。

### 4.4 分期

- per_stage：先按课程阶段+阶段附加费生成桶；未分阶段课程单列桶，other_fees 单列“其他费用”桶（默认日期 null）。总优惠按桶金额权重分配，余分按最大余数、同余按顺序；每桶分期为桶原额−分摊优惠。无新增内容/优惠时，与 v1 per_stage 结果逐分相同。全额为 0 时不分配优惠，保留非空阶段的 0 元期。
- custom：保留 ratio_bps 合计 10000 的老规则，按**最终 total** 最大余数分配；300.01 两期 50% → 150.01/150.00。
- fixed：顾问手填各期 amount；服务端转分验证合计=total，不按比例偷偷改金额。存草稿可暂不等；对外流程按 §4.8。
- 完整 total 未知时，不输出已确定的 payable installments；computed.installments=[]，另给输入预览 `installment_status:"pending_quote"`，原 fees 输入不丢。

### 4.5 阶段待定

pending=true 的阶段可保留课程作为工作草案，但该阶段金额视为未知，不把其行加到 known_amount。computed 保留 `draft_amount` 方便顾问看试算，家长/分享渲染时去掉该草案字段和待定阶段内部草案课程，只显示 pending_note。关闭 pending 后按已有输入重新计算。

### 4.6 computed 读模型

| 字段 | 类型/说明 |
|---|---|
| currency | 固定 CNY |
| stages | `{key,months,calendar_weeks,teaching_weeks,weeks_display,units:number|null,known_units,amount:number|null,known_amount,draft_amount:number|null,pending:boolean}`[] |
| lines | `{line_id,amount:number|null,units:number|null,optional:boolean,pricing_source}`[] |
| unassigned | `{amount:number|null,known_amount,units:number|null,known_units}` |
| subtotal / discount | `{amount:Money|null,known_amount:Money}` |
| total | `{amount:Money|null,known_amount:Money,units:number|null,known_units:number,bundles:string[],complete:boolean,has_tbd:boolean}`；has_tbd 表示有活动另议行（包括可选费用），可选费用仍不计入总价；兼容旧 total.amount/units/bundles |
| installments | `{stage_key:string|null,label,due:Date|null,amount:Money}`[] |
| installment_status | balanced / unbalanced / pending_quote |
| optional_fees | `{line_id,course_id:string|null,label,amount:Money|null,price_text:string|null}`[] |
| budget | 原 cap/remaining/over；total 不明时 remaining/over=null，不能误报预算通过 |
| budget_comparison | `{period,cap:Money|null,comparable_amount:Money|null,over:boolean|null,reason:string|null}` |
| cover_numbers | 沿用原显示结构，不从模型拿数值 |

known_amount 是“目前确定金额”，不是对未定项目的折算报价。total 未知时 discount.known_amount=0，total.known_amount=subtotal.known_amount；避免对部分已知价先减全额优惠造成误导。

### 4.7 预算

total 直接与完整报价对比。year/month 仅当整个报价覆盖恰好一个完整自然年/月且期间明确、无额外范围外费用时比较，其他返回 comparable_amount=null、reason=`period_not_comparable`，提示“预算按年/月描述，请确认方案周期”。不把 18 个月报价擅自按 12/18 平均分摊。旧 budget_cap 的 over_budget 阻断和主管 force 例外原样保留；新自由课程不会绕过。

### 4.8 保存与对外检查（拟定，需确认）

- 草稿允许业务字段留空、待定阶段/未报价课程、未平衡 fixed 分期，保存成功并 warnings 提醒；类型、长度、ID 归属、日期合法性和图库授权仍严格校验。
- 拟定：发送/导出允许“阶段待定”，只展示待定说明；但非待定阶段中的 manual 未报价且 price_tbd=false 不允许发送/导出；price_tbd=true 且 manual_unit_price=null 的行允许发送/导出、对外显示“另议”。total.amount=null 时显示“已确定部分 known_amount + 另议项”，不把未知记为零。所有签约必须 complete=true、total.has_tbd=false、分期 balanced、无未知报价。
- 非价目表行对发送/导出需提交 `acknowledgements:{manual_pricing:true}`，关联本次 version/revision，记录审计；不能持久免提醒，手工改价后重新确认。不额外要求 prices.write；只有本方案编辑权限。
- ad_law_terms 仍阻断 send/export，不能 force；方案正文的加粗/列表在检查前也取可见纯文字，不能用标记拆词绕过；over_budget 仍只有主管可按既有规则 force，签约必须针对已通过检查的发送修订。
- 图库归属/同意/资源授权为硬约束。自由填写并不等于允许跨机构引用或绕过媒体同意。

### 4.9 日期平移

`POST /plans/{id}/shift-dates/preview`，输入 `{version,months:integer(-120..120)}`；仅预览，不写库、不计 AI 次数。移动 basic.plan_date、path 起止月与 legacy_range 日、阶段 nodes.date、timeline.items.date、meta.start_month/target.month、fees.due_dates/custom[].due/fixed[].due，null 不变；同一源日期只移动一次。月末夹到目标月最后一天（2028-01-31 +1 → 2028-02-29），年份越界 422。预览另返回 `save_options:{date_shift:{months,base_version}}`；确认 PUT 携带该 date_shift。服务器先按 base_version 复制并平移原工作稿作为比较基准，再校验/合并已平移的完整 doc，**不把候选 doc 再移动一次**，这样保留旧 legacy_range 的日精度而不信任客户端伪造只读日期。若人工单独改了阶段月份则按 §2.5 清除旧日级范围、重建月首月末。**不改正文里提到的日期、不改数量、单价、旧发送修订和截止令牌**；响应 changes 提醒检查文字。预览返回 `{doc,computed,changes,save_options,warnings}`；确认走普通 PUT，过期 version 409。平移会影响周数/月份展示，不自动重新推算课程量或总价。

### 5.1 版本、建议采用和临时 ID

- `version` 与当前行不一致：409 `version_conflict`，details.latest 为完整有权读取的编辑器 DTO（不含无权原文）。v2 保存不能把已转换文档写回 v1，409 `doc_version_conflict`。
- `applied_cards`：`[{suggestion_id,card_ids:string[]}]`，至多 30 组，每组至多 60 个。所属机构、plan_id、base_version、建议存在/未过期、card ID、依赖都验证；与保存 doc 的变化逐字段一致。它仅作采用审计，不让后端自行应用卡片。
- **修改后采用**：另加 `edited_card_ids`，必须是该组 card_ids 的子集。对这些卡仅验证归属和作用范围，最终 doc 仍过正常业务校验；审计记 edited，不声称内容与 AI 原文一致。不包含 edited 的卡必须与相应 after 相符。
- 若勾选的课程卡依赖新增阶段卡，必须同时采用依赖，或顾问把课程改绑到现有阶段/null 后作为 edited 卡采用；不能背地里替顾问采用别的模块。
- 只在成功保存后记采用；失败不消费建议。服务端映射本次全部 tmp_ 引用（stage/group/line/node/member/fee/installment/photo），响应 id_map；相同 tmp_ 重复声明 422，引用同一声明合法。
- 新 v2 的组/节点等元素属于 JSON 内 ID，使用新增元素登记表约束所有权；原 stage/line 的 plan_elements 不改表、不换旧 ID。

模板里的库价格是历史说明，不是新报价；不把当时的 computed 当成价格表。保留 manual 手填价须明确标记，实例化时仍标“非价目表”。

| POST /plan-templates | `{name,description,applicability,source:{plan_id,version,revision_id?},doc}`；doc 为确认后的脱敏预览 | 201 `{template,warnings}`；再次校验来源/脱敏，不信任前端预览 |
| GET /plan-templates | `origin=all/tenant/platform&subject=&q=&offset=0&limit=50`，limit≤100 | `{items:[模板摘要],total,next_offset,warnings}`，不带 doc 全文 |
| GET /plan-templates/{id} | 无 | `{template,warnings}`，含 doc；无权/缺失 404 |
| PUT /plan-templates/{id} | `{version,name,description,applicability,doc}` | `{template,warnings}`；完整替换，不改来源审计 |
| DELETE /plan-templates/{id} | `{version}` | `{ok:true,warnings:[]}`；软删除，不删已经生成的方案 |
| POST /plan-templates/{id}/instantiate-preview | `{version,shift_months:integer(-120..120),pricing:"current"}` | `{doc,computed,price_list_rev,checks,warnings}`；映射本机构 ID，返回 tmp_ 元素，清空姓名/绑定/原文/审计；不创建方案 |
| POST /plans | 原来源输入 + `{template:{id,version,shift_months,pricing:"current"},doc,expected_price_list_rev}` | 201 编辑器 DTO；doc 为顾问确认的预览，可修改基本信息，正常重算与归属检查 |

实例化 `pricing` 本轮固定 current：库课程取本机构当前已定价课程；manual 保留模板明确的人工单价并提醒，null 仍待报价。缺失/停用/未定价库课程不静默删掉或改名匹配：保留为待处理行并在预览 checks 标注，最终保存前由顾问选择有效库课程或明确转换 manual。服务器不自行把历史库价格变成当前有效报价。

platform 模板的 PUT/DELETE 固定 403 `readonly_template`。机构复制平台模板可用 `POST /plan-templates` 的另一个来源分支 `{source:{template_id,version},...}`，形成独立 tenant 副本后再改；不改平台发布件。任意来源必须二选一，不接受同时 plan_id 与 template_id。

新建 v2 绑定身份沿用 v0.4.1 的 student_id/source_lead_id/prospect 规则；没有身份时先建立**方案内意向来源**，不假造 CRM 线索。模板本身则完全不需要绑定身份。

### 6.3 权限

使用 plans 模块开关；增加 `can(user,policy,"plan_templates","read/write")` 和 `plan_references.write` 权限点（不新建收费模块开关）。主管/教务/顾问可读写机构模板、标参考；财务只读方案，不默认开放模板全文/原文/AI；老师/家长/学员不开放库。平台样例员工也须有 plans 模块和 plan_templates.read。super_admin 的平台发布走现有 ops 身份，不能用普通机构会话。GET /me 在原 capabilities 中增加 `plan_templates:{read,write}` 与 `plan_references:{write}`，前端按能力开关操作，不硬编码角色；原 me 已有字段保持不变，新能力对象不含 tenant_id。

### 6.4 随学科包发布平台示例

扩展现有学科包 `content.sample_plans`（缺失默认 []）：最多 2 个/学科，每个 `{key,name,version:integer≥1,doc_version:2,description,applicability,doc}`。key 与同学科下样例稳定，修内容不换 key，version 增加；整个包的 pack_version 仍是语义版本。

- Claude 提交脱敏 JSON；GPT 校验并随现有 `/api/ops/subject-packs` 创建/更新草稿、`/{key}/versions/{pack_version}/publish` 发布，**不新增另一套平台发布入口**。
- 平台样例 doc 中 stage_type_key/course_key 必须引用同一包的稳定 key；禁止 tenant_id、course_id、teacher_id、student_id、图库 ID、联系人、机构品牌与真实学员原文。所有库单价保持 null，不把枫琴价格当客户机构价目。
- 导入本机构时沿用 pack 稳定 key→本机构 ID 映射；样例的转换必须与包导入同一个事务，失败整次 422 回滚。找不到映射/重复 sample key/无效引用都不能发布或导入。
- 再导入仍只追加缺失 key，不覆盖机构课程和旧模板；机构只看自己已导入且有授权包版本内的样例。已安装旧包不会自动追随新版；显式导入新发布版本后，sample 同 key 的新版只读样例可用，旧引用仍按旧 pack_version 可读。
- 被采用到方案后新建自己的 doc/context，之后平台样例更新不改变已有方案。平台样例不计入“本机构过往案例”检索，除非机构主动存成自己的模板。

## 7. 相似方案检索：后端内部契约

**不设置机构端“查相似案例列表”公开接口**，也不向模型开放 SQL。它是 brief / stage-courses / fill-from-consult / adjust 的准备步骤，机构只看最终建议，不看参考 ID、匹配分、数量或来源。联调不需要前端先调检索接口。

### 7.1 优秀方案标记

`PUT /plans/{id}/reference`：`{version,reference_version:integer≥0,enabled:boolean,revision_id?:string}`；未标记时 reference_version=0。使用方案 version 校验当前可读版本，但 reference.version 独立增长，reference_version 不符返回 409 version_conflict（details.latest 为当前 reference），**不修改 plans.version、工作稿、签约锁或旧修订**。缺 revision_id 时锚定当前修订；对于签约方案可标已签修订。返回 `{reference:{enabled,version,revision_id,updated_at},warnings:[]}`。再次选择其他修订才更新参考内容，不跟随工作稿漂移。取消标记后立即停止作为优秀案例来源，但若同时属于签约来源仍可被引用。

### 7.2 候选和排序

只读本会话机构，排除删除/归档来源、目标方案自己与重复修订。候选依次来自：已签约的 signed_revision（不是工作稿）、未删除机构模板、enabled 的优秀参考固定修订。相同 doc 哈希或相同方案签约+优秀只留一份。

内部查询输入：`{tenant_id(会话注入),exclude_plan_id,subject,direction,grade,budget:{amount,period},target_types,limit:5}`。绝不接受客户端传 tenant_id、候选 plan_ids、外机构模板或模型生成的候选 ID。subject 必须相同，其余只用于排序，不因写法不一把全部候选清空。

可复测的排序：方向规范化精确匹配 +30；年级精确匹配 +20；同 budget.period 且预算区间重叠 +15；target_types 至少一项交集 +20；来源同分按 updated_at 降序、稳定 ID 升序。方向仅做大小写/空白规范化，不让 AI 改检索条件。安全候选多于 5 取前 5，3–5 正常；不足 3 用实际数量，0 也可生成，不为凑数跨机构。

### 7.3 发给模型的摘要

内部返回 `{structural_references:[...]}`，每项只含：模块顺序、匿名阶段名/相对月偏移/时长/目标类型、通用课程组合/频率/数量、**服务器计算的金额区间**（非逐人精确报价）、节点类型/相对日期、匿名策略和测评的短写法摘要。每份最多 1200 字、最多 5 份；不再为摘要额外调用模型或扣次。

禁止：学生姓名/昵称标识、家长姓名、联系电话、邮箱、就读学校、精确住址、自由咨询原文、机构外 ID、原测评全文、附件/照片/隐私二维码、模型可反向访问的链接。测评摘要最多 160 字，策略最多 240 字；先从明确的能力/目标结构抽取通用表达，再移除已知人名学校与联系方式；不能确定已脱敏的自由段落直接舍弃，仅发结构，**不能承诺靠手机正则就能完整脱敏**。

如模板中保留的是学校名称：区分“目标院校类型/层次”与“学员当前就读学校”，对检索摘要统一用目标类型，不发具体校名，防误披露。课程名/阶段名等短字段同样需脱敏，不能只检查 assessment。

摘要只进当前请求内存和必要的短期模型请求上下文，不进入公开建议/basis/warnings/前端审计下载。不返回“参考了 N 份”。内部审计仅保存选择 ID 的哈希/摘要版本/数量与耗时，不存原文。预计多 2000–6000 token 是设计估计，实际按 usage 计量；不训练/微调、不建向量服务，不新增 Cloudflare 绑定或 DeepSeek 模型设置。

## 8. 常驻长输入框：原文保存和一次生成

### 8.1 员工原文接口

独立新增 `plan_briefs`：tenant_id、plan_id、加密 text、version、updated_at/by，复用现有加密密钥。原文**不放在公开 doc_json、plan_contexts、plan_revisions、CRM 备注、模板或案例摘要里**。只保存最近一次确认保存的原文，不悄悄追加到学员档案；新增表纳入既有加密备份与恢复白名单。

- `GET /plans/{id}/brief` → `{brief:{version:0,text:"",updated_at:null},warnings:[]}`（未保存）或实际数据。
- `PUT /plans/{id}/brief` → 输入 `{version:0,text:"…"}`，text≤8000 码点，可空清除；响应 `{brief:{version:1,text:"…",updated_at:"2026-11-17T21:00:00+08:00"},warnings:[]}`。
- 仅 plans.write；财务只读、家长/学员/老师不返回原文。signed/archived 同样禁止修改，复制时默认不复制原文。
- 乐观锁只比 brief.version，不动方案 version；冲突 409 `version_conflict`，details.latest 仅此 brief 对象；超限 422，不截断原文。
- **原文保存成功不等于方案模块已经改动**。AI 失败时原文仍保存，方案保持原值，便于补充后再试。

### 8.2 一次提交的实际调用顺序

选择**一个模型动作 `plan/brief`**，不串两个计次动作：

1. 前端有未保存的方案编辑时先普通 PUT 保存，拿到最新 plan.version（保存失败不启动 AI）。新方案先按原来源规则创建草稿。
2. PUT brief 保存大输入框原文，拿到 brief.version。
3. POST `/ai/plan/brief`，带 UUID Idempotency-Key，一次拿回跨模块卡组（含文字、阶段和课程）；fast 120 秒，deep 150 秒，整个请求共用硬截止；成功只计 **1 次**。
4. 前端在本地逐卡采用/编辑/不要，可撤销；对整个选中集合做 quote-preview 取得服务器报价。最终普通 PUT 保存业务 doc 与采用审计；AI 接口不做第 4 步。

前端一次按钮可以编排前三步，但不能声称这三个 HTTP 请求是一个数据库事务。原文已保存而生成失败时提示“原文已保存，生成未完成，可重试”；不回滚原文、不写 CRM、不收成功次数。

### 8.3 brief 请求

`POST /ai/plan/brief`：

```json
{"plan_id":"pln_demo","doc_version":2,"plan_version":7,"brief_version":3,"scope":"auto","tier":"fast"}
```

scope=auto 或 11 模块之一。auto 自动判断填写/修改，同一原文可包含情况描述和明确修改要求，不另要 intent；可增 `instruction:Text(1000)` 作为补充要求但不取代原文。选定模块只产生该模块卡，不能借选 courses 自动改 path；允许输出依赖提醒或未分阶段课程。

请求不接受客户端参考方案、价格快照、模型名、amount 或 computed。服务端从当前方案/brief/机构课程与规则/安全摘要建上下文。brief 只将必要脱敏内容发模型，电话、姓名、就读学校等不作为写作材料。版本不一致在调模型前 409，且不计次。空原文且 instruction 为空 422。

目标对象：`{plan_id,doc_version:2,base_version:7,brief_version:3,scope:"auto"}`。同一幂等键重放先恢复原响应，再考虑当前版本（不能因期间顾问改过原文就把已成功请求改成 409）；不同请求体复用键按原 idempotency 冲突规则。

### 8.4 建议卡组

保持原响应 `{suggestions,warnings,usage}`。v2 卡组建议 `kind:"plan.v2.cardset"`，payload：

| 字段 | 定义 |
|---|---|
| intent | fill / adjust / mixed，解释当前动作，不要求前端另行判断 |
| cards | 0–60 张；按 module 分组，每张字段见下 |
| completion | `{text:"complete"/"partial"/"not_requested",path:...,courses:...}`，明确没有生成的部分，不假装完整 |
| computed | 只读，**服务器对本建议整组候选应用后的试算**；不是已保存报价，也不代表前端部分采用后金额 |
| price_list_rev | 试算用当前价格修订，供保存 expected_price_list_rev |

每张卡：`{card_id,module,entity_type,op,entity_id,parent_id,field,before,after,evidence,depends_on,default_selected,label}`。

- op=add/update/remove。module 为固定模块 key；entity_id 为稳定元素 ID 或 add 的 tmp_。parent_id 是对应组/阶段或 null。field 是该模块/元素的字段名或 null（整实体 add/remove）。**不接受任意 JSONPath、数组下标、可执行表达式或跨模块路径**。
- 可改白名单就是 §2 中的可写业务字段，但不含身份绑定、subject、consultant_id、style 资源、snapshot、computed、manual_unit_price、优惠金额/比例、分期金额、预算金额的自由推断。预算如有明确原话，模型只能指出 quote；服务端按下述确定解析生成 budget 确认卡，不能采用模型输出的数值。brief 不产生单价、收费、优惠或分期金额编辑卡。
- evidence=`{kind:"quote"/"inference",quote:string|null,verified:boolean,source:"brief"/"instruction"/"plan"}`；quote 只显示当前顾问提供的原话，服务器比对相应文本（去格式但不改词）。核验失败改为 inference，default_selected=false，不能编造原话。
- 有 verified 原话的文字提取卡可 default_selected=true；推断/新策略/新阶段/新课程一律 false。默认勾选仍不自动保存，需顾问点采用。删课程/改数量等影响价格的卡即便有原话也默认 false。
- before 由服务器读取 base_version 后重建，不信模型“原值”。已有方案 stage_key/line_id 保留；新建用 tmp_；依赖仅引用本组 card_id，形成 DAG，无环，不能依赖另一请求的卡。
- 模型不得输出金额或价格快照；服务端递归移除并重建 computed。旧行用原快照，新 catalog 行当前价；新 manual 行 manual_unit_price=null，不猜“合理价格”。其余合规建议保留，warnings 只说必要的人类提示。
- **预算卡例外仅由服务器产生**：module=fees、entity_type=budget，before/after 形如 `{budget:{amount,period,note},budget_cap}`。从明确的“预算”原话解析人民币元/千/万、阿拉伯数或常用中文数词；有“每年/一年”“每月”才定相应周期，有“全程/总预算”才定 total，其他 unspecified。多个互相冲突金额、区间、无法准确解析的单位/币种不生成可采用金额，提醒人工确认；不得让模型补成单点预算。约/左右写在 note，不转换成保证上限。服务器生成 after，verified quote 也 default_selected=false。改变预算时 cap 同步遵守 §2 的总额规则；非 total 不自动创建 cap，已有明确 cap 的变更需同一张卡明确显示并由员工确认。该卡可影响预算比较，但不是收费或成交价。
- 多种配课方案最多 3 个 suggestions，按 variant 互斥；每个 suggestion 一套完整卡组，不能把两套互斥课程全采用。删除不合规变体后，剩余排第一的 recommended=true（置于 payload）。一个 brief 请求仍只计一次。
- 卡组部分采用后必须本地构造候选 doc 再 quote-preview；不能拿“全卡组 computed”当部分采用的总价。

### 8.5 失败、限额和重放

沿用机构每日额度与 fast/deep。校验后 0 条合规建议返回 200、suggestions=[]、warnings 与 usage，计 1 次；模型错误/超时/解析失败 502，不计次；超时 error=ai_timeout。内部解析重试仍最多两次尝试、共享同一硬截止，剩余不足 30 秒不重试，不额外计次。

完整响应快速缓存 10 分钟，之后凭至少 2 天重放凭据 + 7 天建议记录恢复建议顺序/usage/warnings，不重新调模型、不扣次。7 天过期不能伪装成原成功，按既有重放到期错误处理。并发同键只允许一组模型调用。建议保存、费用快照采用和业务提交是不同事务，不用幂等缓存替代乐观锁。

## 9. 现有方案 AI 动作如何扩展 v2

| 动作 | v2 输入增量 | 结果/范围 |
|---|---|---|
| POST /ai/plan/fill-from-consult | 原 consult（≤20000）/instruction + plan_id/doc_version:2/plan_version/scope/tier | plan.v2.cardset，以逐字段咨询提取为主，保留 before/after/原话；不自动写 brief 或 CRM；新常驻入口优先用 brief |

| POST /ai/plan/adjust | plan_id/doc_version:2/plan_version、instruction、scope、tier | auto 可多模块，指定只改一模块；v1 老请求仍返回原 plan.text / plan.stage_courses，不混成 v2 |

## 10. 公众号编辑器：轻量行内格式

### 10.1 存储及最终语法

在现有 content JSON 增加 `text_format:"plain"/"inline_v1"`。旧记录缺失按 plain，原字符原样兼容、不读时迁移；新公众号编辑器显式提交 inline_v1。后端不存 HTML、CSS、颜色代码、DOM 或工具条状态。

| 输入 | 含义 |
|---|---|
| `**文字**` | 加粗 |
| `*文字*` | 斜体 |
| `==文字==` | 高亮 |
| `[[文字]]` | 品牌色强调 |
| `\*` / `\=` / `\[` / `\]` / `\\` | 转义为字面字符；只有这五类反斜杠转义有效，其他反斜杠作为普通字符 |

解析按最长标记优先（先 ** 后 *），每个标记必须同段成对、内容非空，不跨换行、不嵌套。独立的 `[[品牌]]` 不表示链接。仅解释以上格式，其余 Markdown 不自动执行。

不成对、空标记、嵌套/交叉的**整段**降为纯文字：去掉该段内未转义的格式标记，保留内容和换行，保存成功；不把一半标记当成 HTML，不因格式失败 422。转义字面标记原样保留（规范序列化时重新转义）。例：`请看 **重点` → `请看 重点`；`**重点 *斜体* **` → `重点 斜体`（原有段尾空白处理仍沿现有 text() 规则）；完整段 `请看 **重点** 和 *说明*` 保留标记。warnings 给一次可读提醒“部分文字格式已整理为普通文字”，不逐字符弹错误。已是 plain 的同样字符串完全不解析。

允许格式的字段：heading/paragraph/quote.text、list.items[]、table.rows[][]、image.caption。title、brief、article 元信息、来源标签不解析格式，仍为普通文字。7 种 block 的字段名/数量限制不变；basis 仍仅出现在 AI 响应，普通保存删除 basis。

长度按**解析并去标记/反转义后的 Unicode 码点数**计算，沿用当前每类数值上限（text 20000，list item/table cell 3000，caption 1000，标题 200 等）；不把 `**` 占用正文额度。规范化后的序列化单字段另限“可见上限×8+64”字节，整次请求≤1 MiB，防止只有大量标记。plain 旧记录的存量非 BMP 字符不会在读取时改写；新保存统一采用上述可见字数规则。

### 10.2 接口增量与 AI

`PUT /content/{id}` 原形状不变，只增加 text_format。省略时沿用已有值（新建缺省 plain）；`GET` 返回其有效值。article 对象沿用 v0.3.9，图库归属检查不变；这次格式不触碰 article、头图、作者、发布时间、二维码/地址开关。

`POST /ai/content/rewrite|section|versions` 沿用现有请求字段、kind、target、payload 结构；请求可加 text_format，默认当前 content 值。服务端规范化输入，结果 payload 增加 `text_format`。模型需保留未改语句的原格式；改写语句尽量保留既有强调意图，可少量新增 bold/highlight，不擅自给所有字上色。section 的 blocks、rewrite 的 blocks、versions 的 short/medium/long 字符串都按同一语法校验。

- 输出标记不完整按同样规则规范化，不因为标记缺半边丢掉整份合规建议。
- plain 请求继续返回 plain，不要求旧前端识别新语法。
- 不能把格式“保留”解释成改写前后逐字符位置不变；可编辑文本内容本就会变化，保留的是可解析的强调内容/风格。不得借此改 article、图片归属、事实数字或价格。
- AI 仍只返回建议；采用由普通 content PUT 保存，继承原乐观锁、采用审计、quota/幂等和 120/150 秒长文截止。

### 10.3 flags、fact-check、禁用词与 quote

先规范化文本，剥标记/反转义，得到 plain_text，再做事实数字、广告词、缺少出处、引用核验。`最**专业**` 在检查时是“最专业”，不能用标记切碎禁用词来绕过。

所有 quote 返回 plain_text 中的原话；旧 block_index 等字段保持。新增可选 `plain_span:{start,end}` 为**当前 blockText 的可见 Unicode 码点半开区间**，不指向原带标记字符串。list 用 LF 拼 items，table 每行用 ` | ` 拼格、再以 LF 拼行，与原 blockText 一致；image 用 caption。需要高亮时前端自己从 token 映射回 DOM，不拿可见偏移直接 substring 原标记串。

**保持已有检查的业务强度**：方案 send/export 的禁用词检查继续阻断；招生内容在 v0.4.0/v0.4.1 已允许的 flags 提醒行为不改成新增强制拦截。HTML/脚本、跨机构图片、超长和明确不安全内容仍按原规则拒绝。此增量只使检查不受标记干扰，不重新制定发布审核制度。

### 10.4 撤销/重做与导出

50 步整篇快照、打字约 1 秒成一步、顶部工具条/快捷键/块操作条均由 Claude 实现。前端快照包括块内容、顺序、格式与 AI 采用状态；redo 分支在新编辑后清空。撤销到旧内容后再次保存是一次新的 PUT/version，不能删除服务器修订或计次记录。快捷键不触发服务器“撤销”接口。

复制到公众号/导出长图前，前端以受控 token 渲染成 DOM 和白名单行内样式；禁止 innerHTML 插入用户字符串、任意用户 CSS 和远程脚本。品牌色取已授权机构色，文字/背景对比度由实际预览检查，原风格包资源授权、CSP 不放宽。

## 13. 关键错误与前端处理

| HTTP / error | 情况 | 前端行为 |
|---|---|---|
| 401 unauthenticated | 会话失效 | 原登录流程 |
| 403 tenant_expired | 已认证但机构停用/到期 | 保留会话、提示联系机构，恢复后可继续 |
| 403 forbidden / readonly_template | 无权限 / 修改平台示例 | 隐藏或禁用相应操作，不改为本地假成功 |
| 404 not_found | 目标不存在/跨机构/模块关闭 | 统一不存在；公开分享不暴露内部原因 |
| 409 version_conflict | 文档、原文、模板或参考锁冲突 | 保留本地未保存内容，与 details.latest 对比后重试，不能自动覆盖 |
| 409 doc_version_conflict | v1 客户端覆盖 v2 | 提示刷新新版，不把文档转换回旧版 |
| 409 price_changed | 新行报价时价目变更 | 展示本地旧总额与 details.computed.total.amount 最新额，用户确认后用 details.price_list_rev 再保存 |
| 409 invalid_state | signed/archived 编辑等 | 提示复制成新方案 |
| 422 validation_failed | 类型/结构/范围/本方案引用错误 | details.fields 定位字段，显示普通业务文字 |
| 422 invalid_image | 图片不属于本机构图库/不可用于该文档 | 重新从图库选；不暴露外机构信息 |
| 422 template_privacy_review_required | 模板脱敏未完成 | 让员工修改预览，不保存原件到库 |
| 422 legacy_conversion_failed | 旧方案无损核验失败 | 不写库，联系管理员，旧分享仍按原版本显示 |
| 422 idempotency_mismatch | 同 UUID 不同请求体 | 新操作使用新 UUID，不循环重试旧键 |
| 413 payload_too_large | JSON 超限 | 提示缩减内容 |
| 429 ai_quota_exceeded | 当日额度用完 | 沿用 limit/reset 提示，不继续调模型 |
| 502 ai_timeout / ai_unavailable | 模型超时/错误/解析失败 | 原文保留，业务文档不改、不计成功次，重试沿用幂等规则 |

AI 其他既有错误以 v0.4.1 为准，不根据展示文案分支；新增字段不改变旧 CRM 错误码。

`entity_type:module` 的 field 是上表单个字段（不得再包含点、括号或斜杠）；add/remove 模块本体不允许，隐藏/重排仍由员工操作。fees 日期项用 field=due_dates/custom/fixed 输出完整候选数组/对象，服务器逐项保证除日期/label 外金额/比例/稳定关联均与 before 相同。父子对应、引用范围及字段类型由服务端重验。budget 卡是上文明确的唯一 meta 定位例外。before/after 中复杂实体的 schema 就是字段表对应对象；没有兜底的“任意 JSON path”。

对改数量或新增课程的卡，服务器计算该候选的金额。对润色禁止改数量/日期，即使上表一般 adjust 允许。add 的 after 中 entity_id 对应 key/id/line_id 必须等于该卡 entity_id。禁止删除有未处理课程引用的阶段，必须由同组选卡解决引用或将行改为未分阶段。

### A.3 平台样例的可移植 doc 格式

这是 `content.sample_plans[].doc` 的**专用输入格式**，不是带机构 ID 的完整业务 doc，不直接发 PUT /plans。

- 保留 doc_version:2、subject、title、module_order 和 11 个 modules。style 整体省略，实例化时使用本机构默认已授权风格。meta 仅 start_month/target；不包含 consultant_id 或预算金额。
- 结构元素统一使用稳定 key（小写字母起始、随后小写字母数字下划线/短横线、≤80）。普通 v2 的 group/member/node/goal/photo 的 `id`、课程 `line_id` 在平台文件中均改为 `key`；已有阶段字段 key 仍保留。group_id 改 group_key，parent 类引用也使用同样 key。
- path.stage_type_id 改为 stage_type_key（null 或包内 stage key）；课程 course_id 改为 course_key（catalog 必须包内 course key）；不含 origin_course_id/teacher_id/photo_image_id、snapshot、legacy_range、computed 或 adopted IDs。库课程 qty、名称、频率、分钟可填；manual 行没有价格字段。
- fees 只保留 visible/title/installments=per_stage/custom=[]/due_dates/note、stage_extras/other_fees 的 key/label/note 与 stage_key；**不包含金额、优惠或 fixed 分期**。导入后这些费用 amount=null，discount=none，fixed=[]；由机构明确报价。
- basic.student_name/grade 为空，plan_date=null；课程/目标可保留通用英文名。teachers.groups 可空或放虚构“拟任导师”通用说明，不得真实个人；照片页 pages=[]、about.image_ids=[]，封面图不提供。不存在的平台图库资源不靠 URL 绕过。
- 导入映射：本机构 sample doc 的元素 key→确定性 tmp_ 元素，course_key/stage_type_key→机构映射 ID，再套业务 doc 默认值。**每次生成新方案再分配新稳定 ID**；不同实例不能共用模板原 ID。
- 现有学科包对旧 9 类内容的 rejectIds/禁止定价校验保持；新 sample_plans 先分离，走以上专用校验再合回。不能放宽成“sample_plans 内任意 ID 都可信”，也不能让旧递归 rejectIds 把合法结构 key 当成机构 ID。

完整可移植样例见 `examples/platform-sample.json`；它是假数据结构示范，不是 Claude 尚未提供的枫琴正式样例。发布/导入请求继续用原包的整对象格式与 version 乐观锁，不能只 PUT sample_plans 数组覆盖其余设置。

### A.4 公开/家长/导出渲染数据

沿用外壳 `{render_data,manifest,asset_base,warnings}`。v2 render_data.doc_version=2、module_order 同编辑器。模块仍用同名 key；隐藏模块只 `{visible:false}`。不把 GET 编辑器响应当作 render_data。

- 基本姓名由既有 consent/昵称规则生成，basic.student_name 与 render_data.student.display_name 使用同一授权结果；标题、正文等公开文案中也把已知绑定姓名/手填显示姓名替换为同一昵称，不能一处脱敏另一处仍是全名。此为 v2 渲染规则，不能重写历史 v1 修订。
- style.cover_image_id 不作为图片取回凭证，新增/沿用 cover_image_url；photos.pages[].image_ids 转为 `images:[{id,url}]`，about 继续 images；teacher.photo_image_id 转为 photo_url。URL 由当前渠道服务器生成：分享用 `/api/share/{token}/media/{id}`，家长用原 parent media，员工导出用 api_base 的 gallery 授权入口。不能直接给 R2 key 或上传 URL。
- stage.stage_snapshot、课程快照的 course_version/price_list_rev/taken_at、老师源 teacher_id、原文、adopted IDs 和参考标记不返回。stage key/line_id 等仅用于结构展示可保留，不构成资源访问权。
- show_unit_price=false：删除 catalog snapshot.pricing.amount_cents、manual_unit_price 与 optional_fees.price_text/amount，但保留服务端计算的阶段额和总额；自由课程“非价目表”提醒可保留，不展示内部审核按钮。
- 已待定阶段只返回阶段名/pending_note，不返回草案课程、draft_amount 或内部“需要补价格”的技术清单；known_amount 明确标为“已确定费用”，总额未知时不显示最终应付/分期。
- v1 修订不走以上 v2 适配，继续旧 renderPlan 行为和对应前端 v1 渲染分支。示例见 `public-v2.json`。


## 冻结补充：价格另议

- manual 课程 price_tbd 默认 false；只有 price_tbd=true 且 manual_unit_price=null 为活动另议。金额仍为 null，不信任客户端 computed.has_tbd。catalog 不允许 price_tbd=true。
- 任何活动另议行使 computed.total.has_tbd=true；计入总价的另议行同时使 complete=false、amount=null，保留 known_amount。optional 仍不计应付总额/分期，不使 total.amount 变为未知，但另议状态列在 optional_fees 并由 has_tbd 阻止签约；可选 manual 未填单价且未选择另议，同样不允许对外。已填价的行不是活动另议。整阶段 pending 依原规则表示未知。
- 活动另议和阶段 pending 可发送/导出，不能签约；普通未报价且未选择另议只能存草稿。签约须 complete=true、无活动另议、installment_status=balanced。
- 模型不可擅自选择 price_tbd，顾问选择该标记后才允许对外，AI 自由课程建议仍以空单价、price_tbd=false 开始。
- 本补充覆盖原草案 §4.8、§16.1 中普通未报价的表述；其他已确认规则不变。
