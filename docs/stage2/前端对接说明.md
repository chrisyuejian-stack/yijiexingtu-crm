# 阶段 2 前端对接说明

依据冻结接口 v0.3.3。此文说明已交付的后端，不涉及前端页面实现。所有请求和响应 JSON 均来自最终源码测试的实际本地 HTTP 调用，见[精选示例](前端接口示例.json)与[完整实录](HTTP实录_完整.json)。完整实录包含失败请求，用于错误页面模拟；不存在的后续接口不能据此视为已实现。

## 登录和会话

机构主机测试值为 `https://school.test`，平台后台测试值为 `https://console.school.test`。这只是测试配置，部署时使用独立域名。

根地址 `POST /api/auth/login` 成功返回 `api_base:"/api"`；从 `/{slug}` 登录则 `POST /{slug}/api/auth/login`，返回 `api_base:"/{slug}/api"`。登录成功与 GET auth/status 都带前缀。前端保存该前缀，后续拼接资源路径，不能把路径会话发到根 API。根 Cookie 为 `__Host-yx_session; Path=/; Secure; HttpOnly; SameSite=Strict`；机构路径 Cookie 为原来的 `channel_session; Path=/{slug}/`，由浏览器管理，同源请求携带即可。

多机构响应先返回 `need_tenant_choice:true`、`choices`、`ttl:120`，选择后 POST `/api/auth/login/choose`，body 为选中项的 `choice_token`。令牌一次有效；失败、过期或重复使用都重新登录。浏览器可记机构 slug 以排序，不保存账号或密码。根登录只供主管、顾问、教务和财务；其他三种个人角色走机构专属入口。

`must_change:true` 表示先改密码。沿用 `POST {api_base}/password {old_password,password}`；改密会撤销旧会话，再走登录。员工与家长 me 返回不同对象，家长 me 不含平台权限设置。改 slug、角色、手机号、密码或停用账号后应按失效登录处理。

机构停用或到期时业务接口返回 `403 {error:"tenant_expired",message:...}`，前端显示不可用状态，不应主动注销该 Cookie；恢复后仍有效会话直接重试可用。会话自然过期后返回 401，需要重新登录。auth/status 与根公开 `GET /api/public/tenant-brand?slug=...` 为约定例外；未登录的停用机构登录页和旧公开入口仍 404。根 public brand 对未知 slug 返回通用品牌，不泄露账号。

## 账号、家长与学员

原账号接口继续使用 `{api_base}/accounts`。新员工角色 consultant 可与其他员工角色组合；teacher/student/parent 只能单独使用。主管开通沿用平台主机原接口 `/api/tenants/{id}/supervisors`，不是机构根地址上的接口，也不是新造的 ops 路径。

开家长请用 `POST {api_base}/students/{student_id}/guardians {phone,name,relation}`，relation 为 mother/father/grandparent/other。首次创建才返回 temporary_password，复用家长没有此字段。GET 同路径列出有效绑定；PATCH `.../{link_id}` 带 version 和 relation；DELETE 同路径可带 version。删除立即生效；最后一个孩子解绑后家长 active=0、disabled_reason=no_children，再绑定可自动恢复。人工停用后是 manual，重绑返回 account_disabled，需要主管沿用 PATCH accounts/{id} 先启用。

`POST {api_base}/parents/{user_id}/reset-password` 与 disable 请求体可为 `{}`。重置或停用会撤销对应家长会话，重置返回一次性临时密码。绑定与家长管理仅主管/教务可做。列表里的 disabled_reason 用于区分 no_children 与 manual；不要凭 active 自动决定重绑策略。

家长 `GET {api_base}/parent/children` 返回 items。家长访问原课表、余额、缴费等接口时，多孩子需传选中的 `student_id`，服务器再校验有效绑定；只有一个孩子可省略。余额和缴费仍服从原机构开关。方案、报告和新反馈内容尚未在阶段 2 提供。

学员新增字段通过原 `GET/PATCH {api_base}/data/students/{id}` 读写：`report_class_id`、`source_lead_id` 可空，`nickname` 默认“X 同学”，`parent_consent_media` 写布尔值；原学员 DTO 读回为 0/1，供界面转换。原 CRM DTO 的时间格式保持原样；新家长绑定写接口返回的 created_at/updated_at 使用北京时间 ISO。报告班型资源与模板内容在阶段 3 实施。

## 机构平台管理

平台主机使用原 Access + 超管会话；平台顾问无权操作。GET/POST/PUT `/api/ops/tenants` 已实现。GET 支持 offset/limit（最大200），返回 items/total/next_offset。PUT body 包含 id/version；GET `/api/ops/tenants/{id}` 可读取当前配置。PATCH 不用于这个接口。

配置字段：name/slug/expires_at/staff_seat_limit/logo/login_bg/primary_color/modules/subjects/ai_override/status。expires_at 为 YYYY-MM-DD 或 null，status 为 active/paused。logo/login_bg 接受压缩 PNG/JPEG/WebP 的 data URL 或 null，沿用底座品牌存储。subjects 写入 key 数组（music_interest/music_exam/art_interest/art_exam），响应为 `{key,pack_version}` 数组；本阶段只记录开通选择，模板内容尚未导入。AI 覆盖保存 fast_daily_limit/deep_daily_limit，null 表示使用全局默认，本阶段不会调用模型。

本次 ops modules 可改 content/plans/growth_reports/school_db；只传需要改的键。school_db 初始关闭。返回模块含原 CRM 键；`module_labels.growth_reports="成长报告"`，`module_labels.reports="统计报表"`。原 reports 继续使用原平台模块管理流程，不能把它映射成成长报告。返回对象中的额外存储字段（如 AI 列表数据里的 tenant_id/id）不作为前端写入依据。

停用/恢复：POST `/api/ops/tenants/{id}/suspend` 或 resume，带 version/reason；可带 operation_id。停用不删登录，恢复已过期机构前需先延期。强制全机构下线：POST `.../revoke-sessions`，带 version/reason/confirm_name，confirm_name 必须与机构全名完全一致。此操作单独用于撤销会话，不能用停用来替代。

新接口错误为 `{error,message,details?}`；并发冲突 409 的 `details.latest` 是最新数据，先刷新再决定提交。原 CRM 接口的既有错误字段保持原行为，前端兼容 `error` / `code`，显示 message。跨机构与不存在资源都返回404，不能据此显示“属于另一机构”。

## 当前边界

已提供身份、角色、机构、家长绑定、模块基础和学员扩展字段。content/plans/growth_reports 等模块开关与 can 权限已经就绪，其业务 CRUD、AI、发布、分享及模板导入分别在后续阶段实现。原财务报表查询与导出已验证仍可用；新成长报告接口暂未提供，不能用它当前的404当作成长报告业务验收通过。
