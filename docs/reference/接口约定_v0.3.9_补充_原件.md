# 艺界星途 · 接口约定 v0.3.9 补充（给 GPT）

在 v0.3.8 基础上**只加字段，不改已有字段**。迁移只能 `ALTER TABLE … ADD COLUMN`（有默认值），或者写进现有的 JSON 列。不能删表，不能重建表，已有数据不能丢。可以排在阶段 7 之后做。

## 1. 招生内容 · 文章开头与文末（设计稿 v3「招生内容编辑器 · 公众号」左栏）

`content` 文档增加一个可选对象 `article`，只有 `type = "article"` 时有意义：

```json
"article": {
  "column": "招生 · 寒假集训",        // 栏目，≤20 字；空则前端按场景显示
  "header_image_id": "img_…",        // 头图，必须是本机构图库里的图片；null 表示不要头图
  "author": "星光琴行",               // ≤20 字；空则用机构名
  "publish_date": "2026-11-20",      // 文章上显示的日期；空则用更新日期
  "footer": { "qr": true, "address": true }   // 文末是否附咨询二维码 / 地址与上课时间
}
```

- `PUT content/:id` 接受 `article`（整体替换）。`GET` 返回时没有这个对象就当作 `null`。
- 校验：`header_image_id` 要属于本机构图库，否则返回 422 `invalid_image`。`publish_date` 是 `YYYY-MM-DD` 格式。字段超长返回 422。
- 复制或导出时：`footer.qr` 为 true，就在文末附上品牌包里的咨询二维码；`footer.address` 为 true，就附上机构档案里的地址和上课时间。两样都是只读引用，AI 不能改。
- AI 起草、改写时不改动 `article`。
- 兼容：旧文章没有 `article` 时，前端仍用第一张图片当头图（这是现在的做法）。后端有了这个字段以后，前端改成读写 `article.header_image_id`。

## 2. 成长报告 · 本期反馈条数（设计稿 v3「依据：本学期课后反馈 N 条」）

`GET reports/:id` 增加一个只读字段 `feedback_count`（整数），表示这一期里已确认、包含这位学员的课后反馈条数。前端已经在读这个字段，没有就不显示。

## 3. 课后反馈 · 今天的课列出学员名

`GET feedback/today` 的每一项增加一个只读字段 `student_names: string[]`，最多 6 个。老师首页卡片会显示“学员名 · 时长”，没有这个字段就只显示时长。
