## 后端（GPT）

### G1. AI 超时和失败原因

**现象**：招生内容“写本节”在快速模式下经常要等一阵，然后报 `ai_unavailable`，多试几次偶尔能成功。

**原因**：快速档总时限只有 45 秒（`ai.js` 第 140 行），而且包含第二次尝试。v0.4.0 改成创意写作后，单次生成常常接近或超过这个时间。

**修改**：

1. 按动作设时限：

   | 动作 | 快速档 | 深度档 |
   | --- | --- | --- |
   | content：section / versions / rewrite；plan：fill-from-consult / adjust | 120 秒 | 150 秒 |
   | 其他动作 | 保持 45 秒 | 保持 90 秒 |

   - 剩余时间不到 30 秒时，不再发起第二次尝试。
   - `max_tokens`：section 用 4096，versions 用 6144。
   - 如果 Pages Functions 对这个时长有限制，请在交付说明里写清楚。

2. `aiFailure` 记录失败原因，取值：
   - `timeout`
   - `provider_http_<状态码>`
   - `protocol_invalid`
   - `response_too_large`
   - `other`

   不记录用户输入，也不记录模型返回内容。优先复用现有的 metrics JSON，不加列。平台接口“AI 用量”按原因统计失败次数，请写明返回字段。

3. 机构端错误码：
   - 超时返回 `ai_timeout`；
   - 401、402、404 和其他原因仍返回 `ai_unavailable`；
   - 一律不计次数。提示文案由前端负责。

### G2. 方案 AI 写入位置名称容错

**现象**：“整理咨询记录”提示“已丢弃越界文字 path：about / assessment.text / assessment.goals”。

**原因**：DeepSeek 写的位置名称省略了 `modules.` 前缀，导致整条建议被丢弃。

**修改**：

- `textPayload` 先做规整：`assessment.*`、`cover.*`、`fees.note` 等缺少 `modules.` 前缀时自动补上，再走原来的校验。
- 机构介绍（`about`）这类本来就不允许 AI 改的位置，直接忽略，不写进 warnings。
- 在提示词里列出各动作允许写入的位置名称，并附一个完整示例。

### G3. 内容改写支持自由要求

前端规则改为“选中某张卡片时，AI 只处理这张卡片”。为此：

- `content/rewrite` 新增 `mode: "custom"`，配合 `instruction`（≤500 字），按用户这句话改写选中的块。
- 其他 mode 也接受可选的 `instruction`。
- 返回结构不变。

### G4. 图库容量：每个机构 500MB

- 图库要统计每个机构的总字节数。如需加列，请用 `gallery_images.bytes`（`ADD COLUMN`，默认 0），已有图片用 R2 的对象大小回填。回填只写这个新列。
- 平台后台的“机构管理 › 详情”可以调这个机构的上限，默认 500MB。
- 超出上限时，上传返回 413 `storage_full`，并带 `used` 和 `limit`。
- `GET` 图库列表时附带 `storage: { used, limit }`。
- 删除图片后释放容量。

### G5. 顺手两处

1. `content-flags.js` 去掉单字“最”，改成词组（最好的、最强、最佳、最优、最专业、最权威、最顶级、最先进等）。
2. `GET /api/plans/:id` 返回 `party` 和 `party_name`。
