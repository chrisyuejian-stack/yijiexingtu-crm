## 0. 范围与总原则

### 0.1 本文件覆盖什么

艺界星途 CRM「招生」板块下的三个工具（招生内容、课程方案、成长报告）、老师手机端课后反馈、家长端、相关的机构设置，以及平台后台新增的四块：机构开通、学科模版包、模版与风格包、AI 用量。

CRM 原有功能（学员、课表、销课、财务、线索）不在本文件内，只约定本模块要**读取**的字段（见 §4.5.3）。

### 0.2 基础架构假设（GPT 开工前请先确认，有不同意见写进 §9）

- 艺界星途 CRM 以渠道教务系统为底座：同一套 Cloudflare Worker + D1 + R2，沿用其中的 `resolveTenant`、会话、`can` 权限、`repo(env, tenantId)` 等规则。
- 新增的业务表都带 `tenant_id`；新增的 SQL 只写在 repo 层；每次读写都在 repo 内限制 `tenant_id`。
- **机构 ID 只从会话取，前端传来的 tenant_id / created_by / 金额合计一律不信任。**

### 0.3 不可违反的规则

| # | 规则 | 后端怎么保证 |
|---|---|---|
| R1 | AI 只给建议，不直接写库 | 所有 `/api/ai/*` 接口只返回建议对象（§3），没有任何写业务表的副作用。写入只能走普通的保存接口，并带上 `applied_suggestion_ids` 供审计 |
| R2 | 金额由程序算 | 方案的每门课小计、阶段小计、总价、分期，都由服务器按方案里的**价格快照**计算（§4.3.1）；请求里带来的金额字段和快照一律忽略。价目表变了，要按最新价格重算，必须由人明确操作（§4.3.7） |
| R3 | AI 只在机构设置的范围内生成 | AI 返回的课程、阶段类型、维度必须是本机构设置里已有且启用的 ID；不在范围内的整条丢弃，并在 `warnings` 里说明 |
| R4 | 方案总费用严格不超上限 | AI 生成的配法超过 `budget_cap` 的直接丢弃。人工编辑可以超，但导出前检查标红（§4.3.6） |
| R5 | 评分和模拟考分数只能由人填 | AI 接口不返回任何分数字段；报告保存时，评分只接受老师本人或教务提交的值 |
| R6 | 不编造事实 | 招生内容和报告里的事实只能来自机构档案、勾选的资料、课后反馈原文；没有依据的句子要在 `basis` 里标 `unsupported` |
| R7 | 机构隔离 | A 机构的任何接口都读不到、写不了 B 机构的数据；ID 不存在和属于别的机构，统一返回 404 `not_found` |
| R8 | 家长端只露机构品牌 | 家长端和分享链接接口的返回里不出现「艺界星途」字样和平台信息 |

## 1. 通用约定

### 1.1 域名与路径

| 入口 | 地址 | 说明 |
|---|---|---|
| 机构管理端 | `https://edu.yijiexingtu.com/` | 主管、顾问、教务登录 |
| 老师 / 家长 | `https://edu.yijiexingtu.com/{slug}` | slug 是机构代号，由超管设置 |
| 机构端接口 | `https://edu.yijiexingtu.com/api/...` | **机构由会话决定**，路径里不带机构 |
| 公开接口 | `/api/public/...`、`/api/share/...` | 不需要登录 |
| 平台后台 | `https://ops.yijiexingtu.com/api/ops/...` | 只给超级管理员；沿用渠道系统控制台的 Access + 会话做法 |

> 和渠道系统的差别：渠道系统的机构接口带 `/{slug}/api/` 前缀。这里管理者从无 slug 的根地址登录，所以统一改用会话定机构。如果 GPT 认为沿用路径前缀更省事，可以两种都支持，但必须校验路径里的 slug 和会话的机构一致，不一致返回 404。

### 1.2 根地址登录怎么识别机构

现有账号表和手机号索引都按机构隔离，同一个手机号可能在多家机构都有账号。根地址登录按下面的方式确定机构：

1. **新增平台级手机号索引** `platform_phone_index(phone_hmac_platform, tenant_id, user_id)`。
   - 用平台独立的 HMAC 密钥计算，和机构内的 `phone_hmac` 分开。
   - 只给管理角色（supervisor / consultant / academic / finance）的账号建这条索引；老师、学员、家长不建，他们只能从 `/{slug}` 登录。
2. **登录过程**：`POST /api/auth/login {phone, password, turnstile}`，无 slug。
   - 服务器先按平台索引查出候选账号（最多 5 个，超出部分拒绝并记日志），再逐个验证密码。
   - 验证每一个候选账号时都要跑完整的 PBKDF2，结果合并后再返回，这样从响应时间看不出候选账号有几个。
   - **0 个匹配**：返回统一的“手机号或密码错误”，和渠道系统现有的失败提示、锁定规则一致。
   - **1 个匹配**：直接建立会话。
   - **≥2 个匹配**：返回 `{need_tenant_choice:true, choices:[{choice_token, name, logo_url}], ttl:120}`，只列出密码验证通过的机构。前端显示「选择机构」，再调用 `POST /api/auth/login/choose {choice_token}` 建立会话。`choice_token` 一次性有效，120 秒过期。
3. **限流**：登录失败计数同时按 IP 和按平台手机号索引统计，防止有人逐家机构试密码。
4. **记住上次机构**：浏览器可以记住上次选的机构（只存机构 slug，不存账号信息），下次登录在多个匹配中把它排在第一位，但仍然要选择，不自动登录。
5. **另一条路**：管理者也可以从 `/{slug}` 登录，走渠道系统原有流程，不需要平台索引。

### 1.3 请求与响应

- JSON，UTF-8。时间用北京时间 ISO 8601（`2026-11-12T10:24:00+08:00`），日期用 `YYYY-MM-DD`，月份用 `YYYY-MM`。
- **金额**：JSON 里以元为单位（数字，最多两位小数）；数据库和所有计算用整数分。
- **分页**：`?offset=0&limit=50`，`limit` 最大 200；返回 `{items, total, next_offset}`，最后一页的 `next_offset` 为 `null`。
- **并发**：所有可编辑资源都有整数 `version`。`PUT`/`PATCH` 必须带上当前 `version`，不一致返回 409 `version_conflict`，同时附带最新数据。
- **ID**：带前缀的随机字符串，例如 `pln_`、`rpt_`、`fb_`、`crs_`、`stg_`、`sg_`（建议）、`chg_`（修改卡片）、`stp_`（风格包）。
- **写操作**：都记审计日志（谁、何时、改了什么、是否采用了 AI 建议）。

### 1.4 错误格式

```json
{"error":"ai_quota_exceeded","message":"今天的深度 AI 次数已用完，明天 0 点恢复","details":{"tier":"deep","limit":50,"reset_at":"2026-11-13T00:00:00+08:00"}}
```

`message` 是可以直接显示给用户的中文。完整错误码表见 §8。

## 2. 角色、权限与平台规则

### 2.1 角色：在旧 CRM 的角色体系上扩展

旧 CRM 的角色是 `supervisor`、`academic`、`finance`、`teacher`、`student`，校验在 `accounts.js` 的 `rolesInput` 里。规则是员工角色可以 1–3 个组合，`teacher` 和 `student` 是个人角色，只能单独使用，并且必须关联本机构的老师或学员档案。

v0.2 只做两处改动：**新增 `consultant` 员工角色，新增 `parent` 个人角色**。其他规则都不变。

| 角色 key | 名称 | 类型 | 计费 | 登录入口 | 来源 |
|---|---|---|---|---|---|
| `platform_admin` | 超级管理员 | 平台 | — | ops 后台 | 沿用渠道系统控制台 |
| `supervisor` | 机构主管 | 员工 | 计入管理账号 | 根地址或 /{slug} | 旧 |
| `consultant` | 顾问 / 运营 | 员工 | 计入 | 根地址或 /{slug} | **新增** |
| `academic` | 教务 | 员工 | 计入 | 根地址或 /{slug} | 旧 |
| `finance` | 财务 | 员工 | ★ 待 Chris 确认：推荐计入 | 根地址或 /{slug} | 旧 |
| `teacher` | 老师 | 个人（关联老师档案） | 不计费 | /{slug} | 旧 |
| `student` | 学员本人 | 个人（关联 1 个学员档案） | 不计费 | /{slug} | 旧，保留给大龄学员或艺考生 |
| `parent` | 家长 | 个人（关联 1–10 个学员档案，见 §4.10） | 不计费 | /{slug} | **新增** |

角色组合规则（改 `rolesInput`）：
- **员工角色**：`supervisor`、`consultant`、`academic`、`finance` 可以 1–4 个任意组合。小机构常见的“主管兼教务”“顾问兼教务”都可以。
- **个人角色**：`teacher`、`student`、`parent` 只能单独使用，不能和员工角色混用，沿用现有的安全约束。
- **★ 待 Chris 确认**：产品说明里提过“老师兼招生”。第一版不支持一个账号同时是老师和顾问。这种人需要用另一个手机号再开一个员工账号；现有手机号索引是机构内唯一的，所以同一个手机号不能开两个账号。如果这个场景常见，第二版再放开 `teacher + consultant` 组合，届时需要单独做权限裁剪。
- **管理账号数**：拥有任一员工角色、状态为启用的账号数。超过 `staff_seat_limit` 时，新建或启用账号返回 403 `seat_limit_reached`。
- **主管账号**：沿用“主管账号由系统维护创建”，也就是由超管在 ops 后台为机构开主管账号。

新角色在旧 CRM 模块里的默认权限（写进 `permissions.js` 的默认策略）：
- `consultant`：学员只读、线索读写、课表只读；不能看财务和课酬。
- `parent`：同 `student`，看课表、课时余额、缴费的开关沿用机构设置 `student_view_balance` / `student_view_payments`；数据范围限于自己绑定的孩子。

### 2.3 试用与到期

- `tenants.expires_at` 为空表示正式机构；有值且已过期时，该机构所有机构端接口（包括老师端和家长端）返回 403 `tenant_expired`。数据保留不删。
- 例外：`GET /api/public/tenant-brand`（登录页品牌）和 `GET /api/auth/status` 仍可访问，用来显示“已到期，请联系客服”。
- 超管延期后立即恢复，不需要重新登录。

### 2.4 AI 每日上限

- **两档**：`fast`（快速）每机构每天 80 次，`deep`（深度）每机构每天 50 次。数值是平台全局设置，在超管后台修改，**不按机构分档**。超管可以对个别机构单独覆盖，留作试点用（§4.9.4）。
- **按北京时间自然日计**，0 点重置。
- **计数口径**：一次 `/api/ai/*` 请求成功返回算 1 次，不管消耗多少 token；模型报错或超时不计；服务器内部因校验不过而自动重试，也只算 1 次。
- **唯一例外**：批量起草报告（`/api/ai/report/batch-draft`）按学员计次，每成功起草一位学员算 1 次。
- **并发：先预占，再结算**
  1. 调用 AI 前，用一条带条件的原子 SQL 预占名额：在 `ai_quota_holds` 插入一行 `(tenant_id, date, tier, hold_id, user_id, expires_at = now + 120s)`。
     - 插入条件：`已用次数 + 未过期的预占数 < 上限`。
     - 用 `INSERT … SELECT … WHERE` 或 D1 batch 加条件判断，保证多人同时调用时不会超额。
     - 插入失败返回 429 `ai_quota_exceeded`。
  2. 模型成功返回：在同一个 batch 里删除这条预占，并给 `ai_quota_daily.used` 加 1，同时写 `ai_usage` 明细。
  3. 模型失败或超时：删除预占，不计次。
  4. Worker 中途被中断、预占没被释放：120 秒后自动过期，不再占名额。
  5. 批量起草：一次最多预占 `min(学员数, 剩余名额)` 个，逐位结算；剩下没起草的学员放进 `skipped` 返回。
- **单人并发**：每个账号同时最多 2 个进行中的 AI 请求，超过时返回 429 `rate_limited`，防止一个人连点把名额占满。
- **用完**：返回 429 `ai_quota_exceeded`，附 `reset_at`。另一档没用完的仍可以用。
- **试用到期**：返回 403 `tenant_expired`，优先级高于用量判断。
- 每次调用写入 `ai_usage`：tenant_id、user_id、tool、action、tier、模型名、prompt/completion tokens、耗时、结果（ok / error / blocked）。
- **AI 服务**：DeepSeek，用平台的 Key（环境变量 `DEEPSEEK_API_KEY`），机构接触不到 Key。`fast` 和 `deep` 各对应哪个模型，用平台设置配置，不写死在代码里。

### 2.5 功能模块开关

`tenant_modules` 按机构控制：`content`、`plans`、`reports`、`school_db`（留学院校库，第一版默认关）。模块关闭时，相关接口返回 404 `not_found`，前端隐藏入口。只有超管能改。

## 3. AI 建议对象（所有 `/api/ai/*` 通用）

### 3.1 请求公共字段

```json
{"tier":"fast","context":{...},"instruction":"一句话调整的原文，可为空"}
```

### 3.2 响应格式

```json
{
  "suggestions":[{
    "id":"sg_8f2k…",
    "kind":"plan.stage_courses",
    "target":{"plan_id":"pln_…","stage_key":"s3"},
    "payload":{ … 按 kind 定义 … },
    "basis":[
      {"type":"rule","ref":"stage_rule:exam_sprint","text":"考级前 2 个月自动切成冲刺阶段"},
      {"type":"consult","quote":"寒假想多上点课"},
      {"type":"feedback","ref":"fb_…","date":"2026-11-06","quote":"新曲靠背"},
      {"type":"ai_judgement","text":"三级刚过、读谱弱，春季加乐理视唱"},
      {"type":"unsupported","text":"“10 年以上教龄”在机构档案里找不到"}
    ],
    "warnings":["已丢弃 1 门不在课程库的课程"]
  }],
  "usage":{"tier":"fast","used_today":33,"limit":80}
}
```

- `basis.type` 只有 6 种：`rule`（设置里的规则）、`consult`（咨询记录）、`feedback`（课后反馈）、`profile`（机构档案）、`ai_judgement`（AI 判断）、`unsupported`（没有依据）。前端按类型显示不同颜色的来源标签。
- 建议对象在服务器保存 7 天（表 `ai_suggestions`），用于审计和计算采纳率。
- 前端采纳后调用普通保存接口，在请求体里带 `applied_suggestion_ids:[…]`。后端记录“已采纳”，但**不信任 payload**：保存的内容照常完整校验。
- **撤销**：前端维护撤销栈，撤销就是再保存一次旧版本。后端每次保存都写一条 revision（§4.3.1），保证任何一步都能恢复。

## 4. 机构端接口

### 4.1 机构设置（图 10、11、12）

所有设置的写接口需要 `settings.write`，价格相关的需要 `prices.write`。设置改动只影响**之后新建或重新生成**的内容；已有的方案和报告不会被改。

#### 4.1.1 学科包

| 方法 | 地址 | 说明 |
|---|---|---|
| GET | `/api/settings/subjects` | 本机构已开通的学科包：`[{key:"music_interest", name:"音乐兴趣", pack_version:"0.1"}]` |
| POST | `/api/settings/subjects` | `{key}` 添加学科包，从平台模版带入课程、阶段、节点、维度、内容类型（来源标为 `template`）。已有的同名项不覆盖 |

学科包 key 共 4 个：`music_interest`、`music_exam`、`art_interest`、`art_exam`。舞蹈预留 `dance_*`，第一版不开放。

#### 4.1.2 课程库与价目表


**价格快照**：方案一旦存过某门课的价格，就固定使用当时的价格，之后价目表再改也不影响这份方案。

每条课程行保存 `snapshot`，**由服务器在这一行第一次加入方案时写入**，内容包括：
- 课程名、形式、时长
- 计价方式和单价（分）
- 价目表版本号：`courses.version` 加上价目表整体的 `price_list_rev`

```json
{"stage_key":"s3","course_id":"crs_theory","frequency_text":"每周 1 次","units":13,"ai_filled":true,
 "snapshot":{"name":"乐理与视唱练耳","form":"group","minutes":45,"pricing":{"mode":"per_unit","amount_cents":8000},"price_list_rev":17,"taken_at":"2026-11-12T10:20:00+08:00"}}
```

阶段同理：每个阶段保存 `stage_snapshot`（阶段类型名称和规则 key），之后改阶段设置也不影响旧方案的显示。

保存时（`PUT`）服务器做这些事：
1. **新加的课程行**：校验 `course_id` 属于本机构、处于启用状态、已定价，然后按**当前**价目表写入快照。
2. **已有的课程行**：沿用原来的快照，`course_id` 不允许改。要换课，就删掉这一行再加一行新的。课程已经停用不影响保存，只会在检查里提示。
3. **前端带来的 `snapshot` 一律忽略**。服务器按行的稳定 `line_id` 匹配旧快照，前端不能伪造价格。
4. 校验阶段的起止月份连续、不重叠。
5. **按快照**重新计算 `computed`，写一条 revision。请求里带的 `computed` 一律丢弃。

```json
  "total":{"units":49,"packages":["寒假钢琴集训营 1 期"],"amount":11400.00},
```

#### 4.3.7 按最新价格重算（明确操作）

```
GET  /api/plans/{id}/reprice
POST /api/plans/{id}/reprice
```

- `GET` 只返回预览，不写库：`{lines:[{line_id, name, old_amount, new_amount, status:"changed|unchanged|course_inactive|unpriced"}], total:{old, new}, budget_over:bool}`。
- `POST` 请求体 `{version, line_ids?}`：用当前价目表刷新所选课程行的快照（不传 `line_ids` 表示全部），写一条 revision，并记审计「按最新价格重算」。已停用或已删价的课程不能刷新，返回 422 `out_of_scope`。
- 导出前检查（§4.3.6）新增 `price_outdated`（warning）：快照里的价格和当前价目表不一致时提示，并给出「按最新价格重算」入口。
- `sent` 和 `signed` 状态的方案不允许重算，返回 409。要改价，先复制成新方案。

- 只有主讲老师能提交，助教只读。
- 提交窗口是课程开始到结束后 48 小时（北京时间）。
- 提交后状态为待确认：不扣课时、不计课酬。员工确认后才扣课、计酬；退回不产生流水。
- 已确认的出勤，老师不能再改。
- 超过窗口或锁月后，由员工更正。

新增的只是**逐人点评的结构**。旧点评里的「逐人内容」扩展为四段 + 标签 + 曲目 + 照片：

```json
{"lesson_id":"les_…","attendance":[{"student_id":"stu_…","status":"attended"}],
 "public_comment":"全班公共内容（小组课用，沿用旧字段）",
 "personal":[{"student_id":"stu_…","tags":["和弦转换稳","句尾太急"],"repertoire_ids":["rep_…"],"note":"补充或语音转写原文",
   "message":{"learned":"…","good":"…","attention":"…","homework":"…"},"image_ids":["img_…"]}]}
```

接口沿用旧的提交、确认、退回地址：`/api/submissions…` 和 `/api/submissions/{id}/confirm|return`。请求体按上面的结构**向后兼容**扩展：旧客户端只传纯文字点评，照样能用。新增的接口：

| 地址 | 说明 |
|---|---|
| `GET /api/feedback/today` | 老师今天的课和每节课的提交状态（未提交 / 待确认 / 已退回 / 已确认）。数据来自课表和 submissions |
| `POST /api/ai/feedback/compose` | 把标签、曲目和补充文字整理成四段话（只返回建议）。AI 不得加入老师没写的表现 |
| `POST /api/feedback/{submission_id}/{student_id}/copied` | 记一次“复制到微信” |

**谁能看到、什么时候能看到**（和旧规则一致）：
- **默认**：员工确认后，家长端和学员端才看到逐人内容，被退回的不公开。老师在窗口内修改已确认的点评时，家长继续看到上一个已确认版本，等新版本确认后再替换。
- **★ 机构设置 `feedback_auto_confirm`（默认关）**：打开后，老师提交即视为确认，家长立刻看到，适合老师少、不需要审核的小机构。扣课和计酬同样在提交时发生，所以只有主管能开这个开关，开关操作记审计。
- **复制到微信**：只有状态为已确认，或机构开了自动确认时，按钮才可用。这样微信里的内容和系统里公开的内容保持一致。

报告里用到的“本期课后反馈”，**只取已确认的版本**。

```
GET/POST/PUT /api/students/{id}/repertoire
```

字段：曲目或作品名、状态（`learning` 在练 / `done` 已完成）、开始日期、完成日期、图片 ID。

#### 4.5.3 报告批次与报告

```
GET  /api/report-batches?teacher_id=&term=
POST /api/report-batches
```

新建批次：`{name:"秋季学期报告", from:"2026-09-01", to:"2026-12-20", report_class_id?, teacher_id?, student_ids:[…]}`。返回全班列表和进度：未开始 / 草稿 / 完成待发 / 已发。

```
GET /api/reports/{id}
PUT /api/reports/{id}
```

报告对象：

```json
{
  "id":"rpt_…","version":5,"batch_id":"…","student_id":"…","teacher_id":"…","status":"draft",
  "style":{"pack_id":"stp_folio","pack_version":"2.0.0","header_image_id":"img_…"},
  "period":{"from":"2026-09-01","to":"2026-12-20"},
  "stats":{
    "lessons":{"value":14,"source":"crm","crm_value":14,"overridden":false},
    "attendance":{"value":14,"source":"crm","crm_value":14,"overridden":false},
    "repertoire_done":{"value":3,"source":"manual","crm_value":2,"overridden":true}
  },
  "scores":[{"key":"reading","value":3,"previous":2}],
  "mock_exams":[{"month":"2026-11","items":[{"subject":"色彩","score":81,"full":100}],"image_ids":["img_…"]}],
  "texts":{"progress":"…","focus":"…","next_goals":["…"],"home_practice":["…"],"teacher_note":"…"},
  "artwork_image_ids":["img_…"],
  "renewal":{"visible":false,"text":""}
}
```

**`stats` 的来源**：创建报告时，服务器从 CRM 读取以下数据。
- 上课次数：期间内该学生已销课的课次
- 出勤：出勤状态为 attended 的次数
- 完成曲目：曲目单里在期间内完成的数量

读取结果写入 `crm_value`。老师可以在编辑器里改，改后 `overridden=true`，保留 `crm_value` 供对照。

```
POST /api/reports/{id}/refresh-crm
```

重新读取 CRM，只更新 `crm_value`，不覆盖老师改过的 `value`。

其他规则：
- `scores[].previous` 由服务器从同一学员的上一份**已发布**报告里按维度 `key` 取值；**请求里带的 `previous` 一律忽略**。
- `scores` 和 `mock_exams` 只接受人提交的值（规则 R5）。分数超出 1–5，或超出满分，返回 422。

AI 接口：

| 地址 | 说明 |
|---|---|
| `POST /api/ai/report/draft` | `{report_id, fields:["progress","focus","home_practice","teacher_note"]}`。服务器取期间内全部课后反馈和老师打分，每段建议附依据（反馈日期 + 原话）。不和其他学员比较；必须先说进步再说问题 |
| `POST /api/ai/report/batch-draft` | `{batch_id, student_ids}`。为“未开始”的学生批量起草。**只返回建议，不写入报告**；每人计 1 次 AI 用量，配额不够时只处理到配额允许的人数，返回 `processed` 和 `skipped` |

**报告状态**（和点评确认的思路一致）：

```
draft 草稿 ──老师或教务点「完成」──▶ ready 完成待发 ──有 reports.publish 的人发布──▶ published 已发布
   ▲                                    │                                          │
   └──────────────── 退回（附原因）◀────┘                                          │
published ──编辑──▶ 生成新的 draft 版本（家长继续看旧的已发布版本）──再发布──▶ 替换
published ──撤回发布（unpublish，附原因）──▶ ready（家长端不再显示，留审计）
```

| 方法 | 地址 | 说明 |
|---|---|---|
| POST | `/api/reports/{id}/ready` | 老师（自己的学员）或教务提交为“完成待发”。服务器检查：必填维度都已打分；需要作品图的班型已有图；文字段落不为空 |
| POST | `/api/reports/{id}/return` | `{reason}`，退回给老师 |
| POST | `/api/reports/{id}/publish` | 只能从 `ready` 发布；发布后推送到家长端 |
| POST | `/api/report-batches/{id}/publish` | `{report_ids:[…]}`，只发布其中处于 `ready` 的报告，其余在返回里列出原因 |
| POST | `/api/reports/{id}/unpublish` | `{reason}`，撤回发布，回到 `ready` |

其他规则：
- 已发布的报告再编辑时，服务器保留 `published_revision`，家长端只读这个版本，直到新版本发布。
- 机构开了 `teacher_can_publish_reports` 时，老师可以发布自己学员的报告（跳过“完成待发”）。默认关。
- **上一期分数**取自上一份**已发布**的报告。撤回发布的报告不算“上一期”。

### 4.10 家长账号与孩子绑定

家长端的数据权限全部以这张绑定表为准：`guardian_links(tenant_id, parent_user_id, student_id, relation, created_by, created_at, revoked_at)`。

**谁来做**：机构员工在学员档案的「家长」页签里操作，需要 `parents.manage` 权限（主管、教务）。家长不能自己注册，也不能自己绑定孩子。

| 方法 | 地址 | 说明 |
|---|---|---|
| GET | `/api/students/{id}/guardians` | 这个学员绑定的家长 |
| POST | `/api/students/{id}/guardians` | 见下文 |
| PATCH | `/api/students/{id}/guardians/{link_id}` | 改称呼 |
| DELETE | `/api/students/{id}/guardians/{link_id}` | 解绑：写 `revoked_at`，立即生效，家长端马上看不到这个孩子 |
| POST | `/api/parents/{user_id}/reset-password` | 重置家长密码，沿用渠道系统临时密码的做法 |
| POST | `/api/parents/{user_id}/disable` | 停用家长账号 |

`POST /api/students/{id}/guardians` 的请求体：`{phone, name, relation:"mother|father|grandparent|other"}`。
- 本机构里这个手机号**没有账号**：新建 `parent` 账号，返回一次性临时密码（`must_change=1`），并在 `guardian_links` 写一行。
- 这个手机号**已经是本机构的家长账号**：只加一行绑定，不改密码。一个家长可以关联多个孩子。
- 这个手机号在本机构是**员工、老师或学员账号**：返回 409 `phone_in_use`。个人角色不能混用，需要换一个手机号。

**规则**
- **数量上限**：一个孩子最多绑定 4 位家长，一个家长最多关联 10 个孩子。超出返回 422。
- **可见范围**：家长能看到所绑孩子的全部已发送或已发布内容（包括绑定之前的）。解绑后全部不可见。
- **自动停用**：家长的最后一个孩子被解绑后，账号自动停用。之后重新绑定会自动恢复。
- **审计**：绑定、解绑、改称呼、重置密码、停用，都写审计日志。
- **与 student 账号并存**：同一个学员可以同时有本人的 `student` 账号和多个 `parent` 账号，各自登录、互不影响。
- **家长登录**：只能从 `/{slug}` 登录，不进平台手机号索引（§1.2）。
- **手机号存储**：家长手机号存在账号表里，沿用渠道系统的加密方式和机构内 `phone_hmac`。学员表里不存家长手机号。

```json
{
  "id":"newyear-red","name":"新年 · 红金","version":"0.9.0",
  "doc_types":["plan","report","feedback_card"],
  "subjects":["*"],
  "tokens":{
    "color":{"primary":"#A3271F","ink":"#2B1A16","paper":"#FFF8F0","accent":"#F4C08A","muted":"#7A5A50",
             "use_tenant_primary":false},

  },
  "components":{
    "plan.cover":"stage","plan.section_header":"numeral","plan.stage_block":"band",
    "plan.total_card":"solid","report.header":"photo","feedback_card.header":"band"
  },
  "decor":{"cover_frame":"none","corner_image":"assets/cloud.png"},
  "cover_text_modes":["auto","dark","light","panel"],
  "thumbnail":"assets/thumb.png"

```

- **组件变体**：清单由前端代码定义，第一版有这些：
  - `plan.cover`：`stage`、`folio`、`journal`
  - `plan.section_header`：`numeral`、`plain`
  - `plan.stage_block`：`band`、`card`
  - `plan.total_card`：`solid`、`outline`
  - `report.header`：`photo`、`band`
  - `feedback_card.header`：`band`、`plain`
  
  新的版面结构需要前端发版后才能在 manifest 里引用；上传时引用了不存在的变体会被阻断。
- **字体白名单**：`noto-sans-sc`、`noto-serif-sc`、`cormorant-italic`。
- `use_tenant_primary:true` 表示主色跟随机构品牌包。
- **封面文字自动模式（`auto`）**：前端在导出前取主图文字区域，计算平均亮度和亮度方差，规则如下：
  - 平均亮度 ≥0.6，且方差小 → 深色字，叠浅色渐变
  - 平均亮度 <0.6，且方差小 → 白字，叠深色渐变
  - 方差大（颜色杂乱）→ 加半透明主色底板
  
  计算结果写进 `style.text_mode_resolved`，后端只负责保存。

## 7. 后端必须带的自动测试

渠道系统已经有一套隔离和查询预算的测试，请在那套框架上加：

1. **机构隔离**：A 机构账号对 B 机构的每一个新增资源（方案、报告、反馈、设置、图库、修改卡片、分享链接、用量）做读、改、删，全部返回 404；列表接口不出现 B 机构的数据。

   - 老师读不到别的老师的学员报告，也读不到方案和价格。

6. **试用到期**：到期后所有机构端接口返回 403（公开品牌接口除外）；延期后立即恢复。
7. **分享链接**：作废、过期、令牌错误、机构到期四种情况，响应完全一致；数据库里没有令牌明文；单价开关生效。

9. **风格包版本锁定**：发布新版本或停用后，旧方案的 `render_data` 仍然指向旧版本的 manifest。
10. **报告 CRM 数据**：老师手动改过的值，执行 `refresh-crm` 后不被覆盖；`previous` 取自上一份已发布报告，伪造无效。
11. **根地址登录**：
    - 同一手机号在 A、B 两家机构都是员工、密码相同 → 返回机构选择；
    - 密码只和 A 相同 → 直接进入 A；
    - 都不匹配 → 返回统一错误，且候选数为 1 和为 3 时响应时长相近；
    - 老师和家长的手机号在根地址登录失败。
12. **角色组合**：teacher、student、parent 和员工角色混用被拒；consultant 不能改价格；finance 只读方案。
13. **价格快照**：
    - 改了价目表之后，再次保存旧方案，总价不变；
    - 前端伪造 `snapshot` 无效；
    - `reprice` 预览和执行结果一致；
    - `sent` 和 `signed` 状态的方案不能重算。
14. **家长绑定**：
    - 解绑后立即读不到；
    - 一个家长绑两个孩子，只能看到这两个；
    - 用员工手机号绑家长返回 409；
    - 超过 4 位家长返回 422。
15. **反馈确认**：
    - 未确认的点评，家长端读不到；

    - 开了 `feedback_auto_confirm` 后，提交即可见并扣课；

16. **配额并发**：同一机构 20 个并发请求打在剩余 3 次的名额上，只有 3 个成功、其余返回 429；模拟 Worker 中断后，预占 120 秒后释放。

## 8. 错误码

| HTTP | error | 何时 |
|---|---|---|
| 400 | `bad_request` | 参数格式错误 |
| 401 | `unauthenticated` | 未登录或会话已失效 |
| 403 | `forbidden` | 角色没有权限 |
| 403 | `tenant_expired` | 试用到期或机构被停用 |
| 403 | `seat_limit_reached` | 管理账号数已到上限 |
| 404 | `not_found` | 不存在、属于别的机构、模块未开通（三种情况不做区分） |
| 409 | `version_conflict` | version 不一致，响应里附最新数据 |
| 409 | `duplicate` | 重复提交 |
| 409 | `phone_in_use` | 这个手机号在本机构已是员工、老师或学员账号，不能再开家长账号 |
| 409 | `invalid_state` | 当前状态不允许这个操作（如已发家长的方案不能重算、只有完成待发的报告能发布） |
| 409 | `change_stale` | 修改卡片审批时，目标已经变化 |
| 422 | `validation_failed` | 字段校验失败；`details.fields` 逐项说明 |
| 422 | `out_of_scope` | 引用了不在设置范围内的课程、阶段或维度 |
| 422 | `check_failed` | 导出或分享前检查有阻断项；`details` 附检查结果 |
| 422 | `style_pack_invalid` | 风格包没通过自动检查 |
| 429 | `ai_quota_exceeded` | 今天 AI 次数用完；`details`：`tier`、`limit`、`reset_at` |
| 429 | `rate_limited` | 访问过于频繁（登录、分享链接等） |
| 502 | `ai_unavailable` | DeepSeek 报错或超时，不计次；`message` 提示稍后再试 |
