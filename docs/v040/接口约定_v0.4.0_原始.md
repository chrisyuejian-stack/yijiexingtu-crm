## A. 招生内容 AI 改为“创意优先”

产品判断：公众号和新媒体内容需要创造力，机构资料只作参考；方案、成长报告、设置建议仍然严格按框架生成，**这三类不改**。

### A1. 提示词（`ai.js` `protocol()`，仅 tool=content）

- 去掉对 content 的“不得编造事实”和“basis 必须来自资料”的要求。改为：
  - 可以自由创作，可以用常识、行业知识、热点话题、比喻和故事；
  - 勾选的机构资料、课程、往期内容是参考，不必逐句有出处；
  - **不得编造本机构的具体事实**：价格、日期、老师姓名和履历、获奖或录取成绩、学员姓名和成绩。需要这类信息而资料里没有时，写成 `【待填：……】` 占位。
- content 的模型温度提高（例如 1.0–1.2）；plan、report、settings 保持现值。

### A2. 请求新增字段（content 的 outline / section / versions / rewrite）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `tone` | `"formal" \| "balanced" \| "lively" \| "playful"` | 可选，默认 `balanced`。写进提示词。 |
| `references` | 字符串，≤ 8000 字 | 可选。用户粘贴的素材、网页文字、链接，原样作为参考资料传给模型。**服务端不抓取链接。** |

### A3. 过滤改为“提醒不拦截”（`ai-filter.js`，仅 tool=content）

- 去掉按句子标 `unsupported` 的逻辑（第 134 行附近），也不再因为依据无法核对而丢弃建议。
- 只在格式错误、超长、不安全（违法违规内容）时丢弃。
- 每条建议新增 `flags` 数组，前端用来高亮：

```json
"flags": [
  { "kind": "ad_law", "quote": "保过", "text": "广告法禁用：保证效果" },
  { "kind": "banned", "quote": "…", "text": "平台或机构禁用词" },
  { "kind": "fact_mismatch", "quote": "每节 180 元", "text": "价目表为 200 元/节", "source": "prices" },
  { "kind": "needs_confirm", "quote": "去年 12 人考入九大音乐学院", "text": "具体成绩，发布前请确认" },
  { "kind": "privacy", "quote": "王小明", "text": "出现学员姓名" },
  { "kind": "placeholder", "quote": "【待填：开课日期】", "text": "待填写" }
]
```

  - `ad_law`：服务端内置一份广告法常见用语表（最、第一、唯一、保过、包过、100%、国家级、顶级等）。
  - `fact_mismatch`：只比对能确定的：价格、课程名、老师名、机构地址和电话。
  - `privacy`：命中本机构学员姓名（全名）。
  - `quote` 必须能在建议正文里原样找到，否则丢掉这条 flag（不丢建议）。
- `fact-check` 动作结果改为提示性质：`result` 取 `ok | mismatch | needs_confirm`，不得阻止保存、复制或发布。
- 平台和机构禁用词仍然生效，但改成 flag 提示，不再丢弃整条建议。

## B. 先出方案、后建档

现状：`plans.student_id` 允许为空，已有 `source_lead_id`；`POST /api/plans` 要求“学员和线索至少一个”（`plans.js` 约第 496 行）。

### B1. 新建方案三种来源

`POST /api/plans` 在原有 `student_id` / `lead_id` 之外，新增：

```json
{
  "prospect": {
    "name": "必填，≤40",
    "grade": "",
    "parent_name": "",
    "parent_phone": "",
    "direction": "",
    "notes": ""
  },
  "create_lead": true
}
```

- `student_id`、`lead_id`、`prospect` 三者**恰好一个**。
- `create_lead=true`：用 prospect 新建一条线索（stage=`contacted`，source=`方案`），方案的 `source_lead_id` 指向它。手机号按线索现有方式加密，并写 `phone_last4`。
- `create_lead=false`：意向信息存在方案里（手机号必须加密，不得明文入库、不得出现在列表接口里），`student_id`、`source_lead_id` 都为空。
- 校验改为“学员、线索、意向信息至少一个”。
- 方案上下文（`contextFor`）在没有学员和线索时，从 prospect 取 name / grade；昵称默认规则不变。

### B2. 列表

- `GET /api/plans` 每行增加 `party: "student" | "lead" | "prospect"` 和 `party_name`。
- 新增筛选参数 `party`。

### B3. 转为正式学员

`POST /api/plans/:id/convert-student`

请求：
```json
{ "version": 3, "link_student_id": null, "confirm_new": false, "overrides": { "name": "", "grade": "", "parent_name": "", "parent_phone": "" } }
```

- 只建学员档案，**不生成报名、课时或收费记录**。
- 数据来源：overrides > 线索 > prospect。学员的 `source_lead_id` 填线索编号，`parent_consent_media` 默认 0，`status` 为在读。
- 有线索时，线索 stage 改为 `enrolled`。
- 方案 `student_id` 指向新学员，原有分享链接继续有效。方案的 prospect 信息保留（审计需要），不再展示。
- 防重复：同机构有同名且手机号后四位相同的学员时，返回 `409 possible_duplicate`，附 `duplicates:[{id,name,grade,phone_last4}]`。前端可以带 `link_student_id`（挂到已有学员，不新建）或 `confirm_new:true` 再提交。
- 已有 `student_id` 的方案返回 `409 already_converted`。
- 权限同新建学员；写审计日志；用 batch 一次完成（建学员、改线索、改方案、写审计），任一失败整体回滚。
- 版本号不对返回 `409 version_conflict`。

### B4. AI“整理咨询记录”

- 有线索时，咨询资料包含线索的跟进记录（最近 20 条）。
- 没有线索时，只用编辑器里粘贴的咨询记录（现有 `consult`）。
- 方案 AI 的严格规则不变。
