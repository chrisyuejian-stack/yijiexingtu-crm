## 已核对，不构成缺陷

家长。只绑定孩子 B 的账号：`GET /api/parent/children` 与 `GET /api/me` 只有 B。`student_id=A` 的课表、`data/students/A`、`parent/children/A/feed`、`credits/packages?student_id=A`、A 的报告和头图都是 404 或批量读取里的 404；`c2/students` 为 403。不带 `student_id` 时课表只有 B 的那一节，名单里只有 B。同时绑定 A 和 B 时，不带 `student_id` 的课表是 404；带 A 只返回 A 的课和姓名，带 B 只返回 B。`read-batch` 里混入 A 的档案和课表，结果仍是 404，B 的档案是 B。

切换。`yx.js:302-303`：`sessionStorage` 里留着 A 的 id 时，孩子列表只有 B 就选中 B；列表里有 A 才沿用 A。`yx.js:328-333`：下拉改到 B 会改 `yx_child`，并清空 `apiCache` 和 `viewCache`。用这两段源码执行的结果与此一致。课表请求经 `yxScopedPath` 带上当前 `student_id`，缓存键因此按孩子分开。

教师。甲老师的课只有学员甲、乙老师的课和乙班只有学员乙时：甲的 `GET c3/teacher-students` 只有甲；乙的学员历史、乙的课次、`schedule?student_id=乙`、乙班详情和名册为 404 或 403；`data/students` 为空列表；`feedback/today` 的姓名只有甲。乙老师名下的成长报告，甲 `GET` 为 404。`POST c3/templates/preview` 对甲、乙老师都是 403。教务预览能看到冲突，字段是 `lesson_id`、`reasons`（含「学员」）、`date`、`template_id`，没有学员姓名。`c3.js:2108` 的冲突弹窗读的就是这个接口。

边界（按现有权限，不是越权）：学员乙被排进甲老师自己的课次后，甲的 `c3/teacher-students` 和该课次参与者会出现乙的姓名，响应里没有 `parent_name`。成长报告的 `teacher_id` 写成甲时，甲能打开这份报告里的学员 id；写成乙老师时不能。
