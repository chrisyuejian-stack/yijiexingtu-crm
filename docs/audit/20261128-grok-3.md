## G2 取舍

结论：按机构拆 IP 键是对的，它修掉了跨机构误锁。副作用是同一 IP 对每个在用机构各有一轮预算。人机验证关闭时，每个机构 10 次失败 / 小时（锁定约 1 小时）；手机号键仍是每个机构每个号 3 次 / 15 分钟。打一个已知号码时，手机号键更紧，拆 IP 键不会让这一个号更好撞。变容易的是已经知道多个代号、换着号码喷：修前 10 次失败会锁住这个 IP 上的所有机构，现在总次数大约按在用机构数放大。根登录的 `root-login-ip` 仍是全局的，上面的实验里根路径锁住之后，机构路径还能登录。

在用代号可以确认，停用的不行（G6 已验证）。两处都实测过：

1. `GET /api/public/tenant-brand?slug=` 无登录。在用机构返回真实名称；未知代号是占位。连续 25 次不同代号都是 200，没有看到限流。
2. `POST /{slug}/api/auth/login`：在用机构密码错误为 401，未知、停用、到期为 404。

代号由机构自选，规则是 3–40 位小写、数字和连字符，用在登录路径上，不是高熵秘密。拼音或英文简称可以用词表试出来。

建议：保留按机构的 IP 键。另加一条更高的全局 IP 上限，避免预算随机构数线性增加。品牌接口要给在用机构显示真实名称，这可以保留；若不想让词表确认「代号是否在用」，给这个接口和登录的 401/404 差异加上同 IP 限速，或让未知代号与密码错误返回同一种中性结果。不要为了堵住探测把停用机构的真实名称加回去。
