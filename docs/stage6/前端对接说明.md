# 阶段6前端对接说明

依据冻结v0.3.7第0–8节。完整实测JSON见[前端接口示例.json](前端接口示例.json)，逐项见[索引](前端接口示例索引.md)。每个本阶段接口都有成功请求和实际返回，另附冲突、越权、额度不足及批量部分成功。示例数据均来自本地HTTP处理器和模拟数据库/模型；不是线上数据，也不代表真实模型质量。各独立场景的ID不要混用。

## 路径、会话和错误

按登录返回的`api_base`拼接：根会话`/api`，机构路径会话`/{slug}/api`。以下写`/api/...`是接口名称；JSON保留实际测试路径。请求不传tenant_id，新DTO不返回tenant_id；旧CRM接口已有字段保留。带会话、写请求保留同源Origin。示例不导出Cookie；`authenticated:true`表示测试带有效会话。

跨机构资源和未知ID统一404；机构有效会话遇到停用/到期为403 `tenant_expired`，恢复后有效会话可继续使用。关闭growth_reports模块后新增反馈/成长接口404，旧CRM纯文字流程仍可使用。旧统计报表模块`reports`和财务接口完全独立。

新接口校验错误422，冲突409（报告PUT旧version为`version_conflict`，`details.latest`附当前工作稿）。旧review/comments/submissions沿用旧错误体及必填校验，缺旧字段可能400；前端不要据此丢失旧错误提示。

## 反馈：继续用原提交流程

| 方法 | 地址 | 对接要点 |
| --- | --- | --- |
| GET | `/api/feedback/today` | 老师当日课；items含status、can_submit、can_submit_comments；助教可以读自己辅助的课，不能提交 |
| GET | `/api/lessons/{id}/review` | 读课次、participants、最新submission、people、comment_fingerprint及window；有结构化提交时新增personal |
| POST | `/api/lessons/{id}/review` | 主讲老师提交；保留operation_id、kind、previous_id/previous_version、comment_fingerprint及全体people |
| PUT | `/api/lessons/{id}/comments` | 员工更正；全体people仍带participant_id/student_id/comment及原指纹，不改出勤或另扣课 |
| GET | `/api/submissions?status=&from=&to=` | 原员工审核队列 |
| POST | `/api/submissions/{id}/confirm` | `{operation_id,version}`；沿用原确认/销课事务，检查返回blocked，不能把部分受阻当全员已公开 |
| POST | `/api/submissions/{id}/return` | `{operation_id,version,reason}`；退回不扣课、不公开新内容 |
| POST | `/api/feedback/{submission_id}/{student_id}/copied` | 只记录当前已确认、可公开的该学生版本；成功`{ok:true}`；未确认/非当前版本409 |

review的kind为`attendance`或`comments`。每次新操作生成operation_id；同一操作重试保留原编号/原请求，不要拿新内容复用旧编号。previous_id/previous_version和指纹取刚读的review，不能自行补“最新”值。

personal按student_id对齐本课people，可省略，省略就是旧纯文字。每项包含tags、repertoire_ids、note、message四段（learned/good/attention/homework）、image_ids。GET review的新personal还含copied_count。新图和曲目都检查机构、学员归属；不能引用其他学员曲目。未带personal的逐人项使用旧文本规则，不会把旧结构化内容永久遮住。

public_comment是public_text别名；attendance数组`[{student_id,status}]`是people[].attendance别名。同传冲突422；两个别名都不能替代旧people/版本/指纹。不要向不存在的POST /api/submissions提交。

提交窗口为课程开始至结束后48小时，北京时间；仅主讲可提交，助教只读，锁月/超窗由员工更正。默认待确认不扣课、不计酬、不公开。确认后再改点评，家长继续读旧已确认版本；新内容经确认才替换。已确认出勤不能由老师再改。

机构开关沿用`GET/PUT /api/settings`：PUT `{key:"feedback_auto_confirm",value:true}`或`{key:"teacher_can_publish_reports",value:true}`，默认false，仅主管可改并记审计。自动确认复用同一事务；全员无法销课时保持待处理，部分受阻仅实际确认者公开。复制按钮不能单凭开关为true而启用，应以该学生已确认结果为准。

## 曲目或作品单

GET/POST/PUT `/api/students/{id}/repertoire`。GET返回items。POST字段为`name,status,start_date,completed_date,image_ids`（日期可null，status为learning/done）；done需完成日期。PUT仍走集合路径，体内带`id,version`和要改的字段，**不是**`.../repertoire/{id}`。成功POST为201，PUT为200，返回新的version。日期顺序不能颠倒，图片ID须来自本机构。老师限自己关联/分配的学生，员工依growth_reports权限。

## 报告批次与编辑

| 方法 | 地址 | 对接要点 |
| --- | --- | --- |
| GET | `/api/report-batches?teacher_id=&term=&offset=&limit=` | items为批次及reports进度摘要；term按批次名称查，默认limit=50，最多200；返回total/next_offset |
| POST | `/api/report-batches` | `{name,from,to,report_class_id?,teacher_id?,student_ids}`，成功201返回batch和完整reports占位 |
| GET | `/api/reports/{id}` | 完整工作稿，含version/status/progress/options及dimensions_snapshot |
| PUT | `/api/reports/{id}` | 带version，提交修改字段；返回新版本。人工保存后progress=draft |
| POST | `/api/reports/{id}/refresh-crm` | 只刷新crm_value，不覆盖老师的value；生成草稿版本 |
| POST | `/api/reports/{id}/ready` | 检查全部必填维度、文字和需要的作品图，通过才ready |
| POST | `/api/reports/{id}/return` | 员工`{reason}`退回ready到draft |
| POST | `/api/reports/{id}/publish` | 普通从ready发布；授权老师可从draft直发，仍须全部检查通过 |
| POST | `/api/report-batches/{id}/publish` | `{report_ids}`；返回published及skipped，未ready为not_ready |
| POST | `/api/reports/{id}/unpublish` | `{reason}`撤回到ready，家长端立即不可读，保留审计 |

普通POST批次已创建全部报告ID，AI不补建报告。没有显式report_class_id时逐人用学员档案班型；任何人没有班型整批422，前端提示补齐。日期来自批次，报告PUT不修改period/batch/student/class；维度、班型选项、集训识别、统考精确日期在创建时保存快照。

老师创建强制归属自己；员工可指定老师，未指定则null，之后员工用普通PUT `{version,teacher_id}`分配。老师只能读写分配给自己的报告，不能移交给别人。不要用历史主讲自动猜归属。

scores以`[{key,value}]`提交，value只能整数1–5；previous由服务器按同学生上一份仍已发布报告的稳定key读取，传入previous会被忽略。草稿未打分可不列该key；ready要求全部打分。评分/模拟考分数仅本人老师或教务填写，主管单一角色不能代填分数，主管兼教务可填。

mock_exams为`[{month:"YYYY-MM",items:[{subject,score,full}],image_ids:[]}]`，score在0到full内，full>0。texts的progress/focus/teacher_note为字符串，next_goals/home_practice为字符串数组；ready时均不能为空。require_artwork以报告创建时的options快照为准。

PUT可以保存texts、人工scores/mock_exams、stats的value、artwork_image_ids、style、renewal及applied_suggestion_ids。dimensions_snapshot、options、previous、crm_value、只读统计由服务器决定；请不要把它们当可编辑配置。

stats最多三项，来自`settings/report-classes`的options.stats：lessons/attendance/repertoire_done/camp_days/mock_count/days_to_exam及manual_*。未配置沿用学科默认组。手改只传`stats:{key:{value:数字}}`；响应保留crm_value/source/overridden供对照。refresh-crm只更新crm_value，是否采用新值由人决定。mock_count和days_to_exam不接受手改。

camp_days只计报价form=camp且course_type_id显式关联的排课课程，期间内已确认销课按北京时间不同日期计数，同日多节只算一天。识别集合锁快照，报价以后停用/软删不改变旧报告。没有映射时warnings提示核对或人工填写。统考节点calendar的key=unified_exam可填exact_date；只填月份时days_to_exam不生成，有精确日期时在发布时按“考期减北京时间发布日期”计算。

发布保存独立修订和manifest，并产生站内通知；不发送微信或短信。已发布工作稿再编辑变draft，家长仍看published_revision；重发才替换，unpublish才移除。上一份分数按实际发布先后确定，同毫秒也有稳定顺序，撤回的不算上一份。

## 风格与图片

GET `/api/styles?doc_type=report`或`feedback_card`，老师可按新文档类型读取。新内置`stp_growth_folio@1.0.0`支持report/feedback_card，报告默认使用它；旧plan/article包及其版本未改。按接口返回的id/version选择，历史文档使用已锁的manifest；可GET /api/styles/{id}/versions/{version}读取允许访问的锁定版本，成长权限不能借此读取已关闭的旧方案/文章风格。平台上传、发布、默认包管理仍按阶段7安排。

本阶段没有扩大旧图库维护权限或另加上传入口。图片仍通过已有图库流程取得本机构image_id；反馈image_ids、报告artwork_image_ids/mock_exams[].image_ids/style.header_image_id引用这些ID。新选隐藏图被拒，已有引用可继续显示。若老师页面需要新增上传/图库管理交互，应在既有权限及后续明确范围内对接，不假定老师有机构图库管理权。

## 三种AI及采用保存

三个接口都带UUID的`Idempotency-Key`，体内可带tier=fast/deep和instruction。返回顶层suggestions/warnings/usage。只返回建议，业务进度/评分/报告内容不随AI调用改变；采用后再普通保存。

| POST地址 | 请求 | 建议协议 |
| --- | --- | --- |
| `/api/ai/feedback/compose` | lesson_id/student_id/tags/repertoire_ids/note，使用当前未提交表单 | kind=feedback.message，target={lesson_id,student_id}，payload={message:{learned,good,attention,homework}} |
| `/api/ai/report/draft` | report_id及非空去重fields | kind=report.text，target={report_id,student_id}，payload={texts:{仅请求字段}} |
| `/api/ai/report/batch-draft` | batch_id、非空去重student_ids，最多100人 | suggestions同report.text；另有processed和skipped |

报告fields只允许progress/focus/home_practice/teacher_note，next_goals由人写。服务器只给该学生已确认原文、人工评分和报告事实；剔除模型评分、统计与伪造target。basis中可核对的原话有feedback ref/date/quote，找不到依据的文字带unsupported；界面保留人工核对提示，不把AI文字自动当事实或自动打分。

批量只取progress=not_started，按输入顺序分配剩余额度。一批占账号一个并发名额，内部最多4人同时调用，共用45秒快速/90秒深度截止时间，重试不延长；逐人成功计次，批量本身不另计一次。processed含student_id/report_id/suggestion_ids，skipped含同样两个ID和reason：already_started/quota_exceeded/model_error/deadline。至少一人正常完成200；正常但建议过滤为空也计该人一次。无合格者200不计次；有合格者零余额429；实际调用全部错误/超时502不计次。

同一请求重试保留原幂等键和请求体；进行中409，请求体不同422。10分钟缓存后由持久凭据重建原建议顺序、warnings、usage及processed/skipped，不调用模型、不重复计次。显示接口原usage，不自行按当前余额重算重放结果。

采用反馈message后仍走review POST（旧字段一个不能少）；采用报告texts后走报告PUT并附所采用的applied_suggestion_ids。不要把basis整体塞进业务字段。报告AI没有expected_price_list_rev；该字段仍仅用于课程方案配课的价格变动确认，已接入的价格补丁保持原样。

## 家长端

GET `/api/parent/children/{id}/feed`返回分页items/total/next_offset，type=plan/report/feedback。只含绑定孩子已发送方案、已发布报告、当前已确认反馈。反馈items直接有message/tags/repertoire_ids/public_comment/image_ids/image_urls；报告items用id再请求`GET /api/parent/reports/{id}`，返回render_data、manifest、revision_id。

render_data使用机构brand和学生nickname，不包含平台品牌；始终读取已发布修订。解绑后立即404。图片走`GET /api/parent/media/{image_id}`，同时检查绑定、已公开引用及学生照片授权；未同意parent_consent_media时不返回学生图片ID/地址，机构公共头图按品牌图片规则。旧方案图片访问仍由原处理器兜底。图片响应为二进制，JSON示例中的base64仅为前端模拟素材。

## 前端需要完成的部分

本轮仅覆盖用户价格确认补丁，未制作反馈和成长报告界面。Claude接入当日反馈、原审核队列、曲目单、报告批次/编辑器/发布与退回、家长时间线、上述三种AI；编辑与发布按钮按角色、状态、can_*及默认关闭开关控制。既有设置页如需配置顶部统计项或精确统考日期，接入班型options.stats及日历exact_date。JSON可直接用于本地模拟；实际接入替换为登录返回api_base及真实资源ID。
