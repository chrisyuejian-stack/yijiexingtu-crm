## 前端行为要点

- **提交反馈**：照旧调用 `POST /api/lessons/{id}/review`，旧字段一个不少（`operation_id` 在同一次编辑内保持不变，`previous_id` / `previous_version` / `comment_fingerprint` 取自刚读的 review）。`people[].comment` 填四段拼成的一段话，所以旧页面照样能看；`personal` 带标签、曲目、补充原话、四段、图片 ID。每位学员至少要有一段四段内容才能提交。
- **复制到微信**：只在该节课的提交已确认、且该学员有已公开文字时显示，复制后调用 `copied`。
- **AI**：反馈 compose 用当前未提交的表单；报告 draft 固定请求四个字段；批量起草只发送 `progress=not_started` 的学员，最多 100 人。采用后才写进页面，可撤销，保存时带 `applied_suggestion_ids`。老师的 AI 入口按角色显示（服务端按本人主讲 / 分配逐条校验）。
- **打分**：只有老师本人或教务能打分和填模拟考；主管单一角色看到只读和说明，保存时不提交 `scores` / `mock_exams`。
- **统计**：只把手改过的项按 `stats:{key:{value}}` 提交；`mock_count`、`days_to_exam` 只读；`refresh-crm` 只更新 CRM 对照值。
- **完成 / 发布**：`check_failed` 时弹出缺项清单；退回、撤回要求填写原因。

## 验证

本补丁覆盖到阶段 6 源码后：`npm run build` 通过；`npm test`、`TEST_BUNDLE=1 npm test` 均为 469/469。浏览器里用本机预览走过一遍：老师手机端写反馈 → AI 整理 → 提交 → 教务确认 → 家长端看到四段；新建批次 → AI 批量起草 → 老师打分并采用 AI 文字 → 完成 → 主管批量发布 → 家长端打开报告。

## 给后端的两个建议（不阻塞）

1. 家长时间线 `feed` 目前只含结构化反馈。机构从旧流程过来，历史上的纯文字点评不在时间线里；家长端暂时这样处理：一条新版反馈都没有时，沿用旧的上课记录页。后续可以考虑把已确认的纯文字点评也放进 `feed`（如 `type=feedback` 带 `text`），家长端就能统一显示。
2. 老师没有图库权限，所以反馈照片和报告作品图暂时只能由教务添加。是否给老师开放“上传课堂照片”需要产品决定（涉及学员照片授权），本补丁没有假设这项权限。
