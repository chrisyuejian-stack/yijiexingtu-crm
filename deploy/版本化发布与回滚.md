# 版本化发布、一键更新与回滚

2026-11-18。本轮新增；原业务代码、接口和0001–0028迁移未改。以下命令是给腾讯云网页终端使用的操作单，本轮没有在实际服务器执行。

## 文件和目录

```text
/opt/yijiexingtu/releases/<版本号>/       每个版本独立、只读代码与依赖
/opt/yijiexingtu/current                  指向当前版本的软链接
/var/lib/yijiexingtu/crm.sqlite           持续保存的业务库，更新不替换此文件
/var/lib/yijiexingtu-deploy/deploy/       root私有发布台账和部署锁
/var/lib/yijiexingtu-deploy/release-snapshots/ root私有更新快照、元信息、独立恢复工具
/etc/yijiexingtu/app.env                  持续保存的环境配置和原密钥
/etc/yijiexingtu/maintenance.flag         维护标记，Nginx全入口503
```

只保留最近5个受管理的代码版本，包含当前版本和可回退的上一版本。第6次保留时自动删除最旧的受管理代码目录；不删除配置、业务库、媒体或更新快照。旧版本带有完整依赖副本，不依赖可能被清理的其他版本目录。快照独立保留，需按负责人确认的保留策略人工管理，避免磁盘用尽。快照含真实数据库原文，目录root:root、700，文件600；应用用户yxt不能读取或改写恢复工具。不要把快照发到聊天或公开下载目录。

## 1. 生成固定格式部署包（给开发人员）

在本次完整源码的根目录运行：

```bash
npm run package:tencent
```

这条命令先实际运行原 `npm run build`，再生成 `deploy/packages/` 中带唯一版本号的ZIP和同名 `.zip.sha256`。也可指定版本和输出：

```bash
npm run package:tencent -- --version 0.5.0-tencent.20261118.release1 --output deploy/packages/yijiexingtu-tencent.zip
```

不要复用已安装的版本号；同名输出文件或已存在版本会拒绝覆盖。包根目录直接包含：`dist/`、`backup-dist/`、`server.mjs`、`platform/`、`migrations/`、`deploy/`，以及必要的 `package.json`、`release.json`、`SHA256SUMS`。不套外层目录，不携带src、scripts、tests、node_modules、数据库或真实密钥。

`release.json`记录版本、最大迁移编号、每条迁移的名称/哈希、两个Worker哈希。`SHA256SUMS`覆盖其余全部文件。上传时ZIP和外部`.zip.sha256`放在同一目录，勿改文件名；后者校验整个ZIP。内部校验要求没有多余或遗漏文件。SHA256用于传输完整性校验，不替代可信来源审核。

新服务器首次安装可用这个运行包：先在空目录解压，再按README运行其中 `deploy/install.sh`。运行包直接安装预构建产物；完整源码安装则先生成同一格式的包。首次安装脚本不导入业务库、不启动空系统，仍需按README完成迁移预演。检测到已安装current时，install.sh会停止，后续一律使用update.sh。

## 2. 一键更新（给用户）

把开发者交付的部署ZIP和同名`.zip.sha256`上传到 `/root/yxt-upload`。在root网页终端进入当前版本，复制下面两行；把最后的ZIP文件名替换为实际文件名：

```bash
cd /opt/yijiexingtu/current
bash deploy/update.sh /root/yxt-upload/艺界星途_v0.5_腾讯云版本化部署包_20261118.zip
```

**首次接入这套更新器时**，旧current中可能没有update.sh。请把本次部署包解压到root私有新目录，先核对外部SHA256，然后用包内更新器启动本次更新，不要覆盖旧版本里的任何文件：

```bash
cd /root/yxt-upload
sha256sum -c 艺界星途_v0.5_腾讯云版本化部署包_20261118.zip.sha256
mkdir -m 700 /root/yxt-upload/updater-20261118
unzip 艺界星途_v0.5_腾讯云版本化部署包_20261118.zip -d /root/yxt-upload/updater-20261118
cd /root/yxt-upload/updater-20261118
sha256sum -c SHA256SUMS
bash deploy/update.sh /root/yxt-upload/艺界星途_v0.5_腾讯云版本化部署包_20261118.zip
```

目标目录已存在时请用新的空目录名，不要向旧解压目录混入文件。正式上传包已经有完整产物，不需要用户重新打包或改业务文件。

更新器按顺序自动执行：

1. 取得部署锁；安全解压并验证全部SHA256，拒绝路径穿越、符号链接和多余文件；准备新版本依赖。数据库、迁移历史、目标版本检查失败时，业务服务继续运行。
2. **停写前**用Node原生 `node:sqlite backup()`生成online一致性快照。在线快照失败不进入停机。
3. 写维护标记，停止主服务并等待数据库进程锁释放；再用backup()生成frozen一致性快照，包含在线快照后、停写前最后完成的写入。恢复默认选frozen。
4. 检查迁移台账，跳过已执行的同名同哈希迁移。对全部待执行SQL开启一个 `BEGIN IMMEDIATE` 事务，每个文件一个SAVEPOINT。任意SQL、外键检查或提交失败，整批DDL、数据及台账全部回滚，current仍指旧版本，重新启动旧服务。迁移不得自行BEGIN/COMMIT/ROLLBACK或修改部署台账。
5. 成功后原子替换current软链接，重启systemd主服务。检查新进程实际工作目录确实是目标版本，再请求本机/login；最多等待200秒，避免把旧进程的200响应误当成功。
6. 新版本健康后登记成功、清理到最近5版。原来没有维护标记时解除维护；更新前已处于维护则保持。

本次实际包仍只有0001–0028，**没有新的业务SQL**。首次更新会核对完整已知v0.5/0028结构与原迁移哈希，然后只把历史登记进 `schema_migrations`，**不会重跑旧迁移，不会因此撤销会话**。未知结构会拒绝推断，保留旧服务；不要删台账或重跑0001。后续新包自动执行尚未登记的编号，历史SQL被改、编号缺失或试图用旧包降级时直接停止。

这是一次短暂停机发布，不是零停机。更新锁防止并行更新/回滚；异常断电留下pending时，下一次更新会停止并提示先用rollback.sh恢复。应用配置路径DIST_DIR和BACKUP_WORKER_PATH须保持默认的current路径，DB_PATH必须在持久数据目录，不可放在release内。

## 3. 健康检查失败会怎样

更新器自动停止失败的新服务、切回上一版代码并重启、再核对旧版健康。它**不自动恢复数据库**。

- 没有执行新业务迁移且旧版健康：恢复更新前的维护状态，输出失败原因、回退版本和快照位置，命令以失败状态退出。
- 已提交业务迁移或旧版仍不健康：保持维护503，保留数据库中的更新后数据，并输出 `restoreCommand`。请先把错误和版本信息交给负责人，不要直接解除维护。
- 失败新版本目录会清理；独立快照、元信息和恢复工具不清理，恢复命令仍可用。迁移成功后健康失败、再换一个版本重试，也会保留最初与旧代码兼容的快照恢复命令。

更新SQL失败和健康失败不同：前者事务从未提交，数据库无需快照回退；后者可能已经提交数据库变化，因此只回退代码并停写，等人工判断。

## 4. 一键代码回滚

```bash
cd /opt/yijiexingtu/current
bash deploy/rollback.sh
```

自动选择发布台账记录的上一版本、切换软链接、重启并健康检查。连续回滚继续沿历史往前走；无可保留上一版时会拒绝，不猜目录。若先前更新执行了业务迁移或当前库领先目标代码，会明确输出 `databaseReviewRequired=true`、`maintenanceKept=true`，以及对应快照的恢复命令。不会自动执行它。

若首次接入的新版本失败而回到了不含rollback.sh的历史版本，可继续使用第2节root解压目录中的 `bash deploy/rollback.sh`。正在执行的更新与回滚不能同时进行。

## 5. 人工确认后才恢复数据库

恢复会舍弃快照之后的数据库变更，因此需先判断是否必须回退数据；仅代码有问题时通常不需要恢复。系统输出的命令形式是：

```text
/usr/bin/node '/var/lib/yijiexingtu-deploy/release-snapshots/实际快照.sqlite.restore.mjs' '/var/lib/yijiexingtu-deploy/release-snapshots/实际快照.sqlite' --confirm-data-loss
```

请复制**本次实际输出的完整命令**，不要直接复制带“实际快照”的示意。独立恢复工具会校验快照哈希/完整性、保持维护、停止服务、检查进程锁，先把当前库另存rescue快照，再校验并原子替换。没有确认参数就拒绝；不会自动启动或解除维护。默认部署快照目录与业务库同在/var/lib的一个文件系统；自定义挂载须保证恢复临时文件与业务库同文件系统，否则原子替换会安全失败，原库不被覆盖。

恢复完成后，负责人确认current与快照版本相容；若已有后续迁移，不能让新代码直接使用旧快照。先保留维护启动服务，在本机核对登录、业务数据和图片，再按README解除维护。已经上传的COS媒体不会被数据库快照自动倒退或删除，原件继续保留。

发布快照是完整SQLite，包含schema_migrations；全库SQL导出也包含台账。原CRM业务逻辑备份白名单不改；不要把原业务逻辑恢复当成版本回滚工具。恢复旧完整快照后，下一次发布会重新识别其台账并补跑缺少的新迁移。

## 6. 这次是否需要新云配置

**不需要**新增腾讯云/COS绑定、环境变量、Secret或DeepSeek设置。root私有发布目录由脚本自动建立；原app.env、密钥、桶、域名、systemd主服务沿用。更新器不切DNS，不连接Cloudflare，不请求DeepSeek；新进程仍会执行原启动COS检查。

本地已使用真实SQLite和本机HTTP验证完整代码切换/会话延续，systemctl与COS云端操作使用模拟。实际TencentOS服务权限、实例角色和Nginx需在正式预演复核。失败时保持维护、查看输出，不要绕过脚本手动删除库、迁移台账或快照。
