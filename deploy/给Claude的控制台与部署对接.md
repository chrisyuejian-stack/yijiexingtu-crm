# 给Claude：控制台与部署对接

基准已是合并后的v0.5，本轮只加平台运行层，没有改前端、业务API、模型设置或0001–0028。不要用之前未融合前端的旧包作为起点。

控制台教程请对应这些实际文件与默认值：

- CVM ins-f5ui1gyv，上海八区，101.43.112.196，TencentOS3.3。先提升现有1Mbps带宽（30Mbps按流量或至少5Mbps包月）；保留2核2GB，脚本加2GB交换空间，主Node 768MB。
- COS两个上海私有桶；备份版本控制与非当前版本生命周期。实例绑定yxt-cos-role，策略由render-cam-policy.mjs按真实桶名生成；GetObject覆盖HEAD，DeleteObject覆盖批量删除对象授权。不要用主账号密钥，日常role模式不落盘COS密钥。
- 安全组22/80/443；新Node只在127.0.0.1:8787。安装脚本不启动空数据库，启动要先导入0028完整库。
- 证书需要专用DNSPod API token，保存在root600的cert.env，仅证书用；和COS实例角色分开。Acme脚本自动续期。
- ops Nginx Basic Auth + 原平台密码/验证器；原Access/Turnstile仍显式off，不改源码开关语义。
- Cloudflare维护Pages包拦截全部路径和方法；最终冻结窗口临时暂停原两条Cron并等正在运行的任务结束，保存原配置方便回滚。
- R2读取令牌只授权迁移的原媒体/备份两桶。历史backup_runs随DB迁移，历史备份原件也应复制，否则新后台历史条目找不到对象。反迁需要单独临时写入令牌；不要把原只读令牌冒充写权限。
- 当前最终计数SQL一次返回140表JSON，贴Console后保存counts值为source-counts.json。在线预演源仍变化时不可把不一致标通过，正式冻结再严格核对。
- 预演同两桶时先记录对象清单，停服务后按清单清理新增测试对象；不得在客户已使用后运行预演清理。
- DNS由CNAME改A，两个域名都指向新IP，TTL600。切换前需完成TLS/真实AI/业务/备份恢复预演。
- 原两条逻辑备份任务由主进程运行；额外快照timer北京时间04:00，监测05:00，健康每5分钟。ERROR日志需要配置采集与通知渠道，不能仅有脚本就声称短信告警已通。
- 没有任何真实云端操作由本轮GPT执行。所有本地测试结果和局限在测试结果.md。

用户服务器命令从deploy/README.md开始。基准说明中的旧Cloudflare部署步骤作为历史记录保留；本次不用重新跑业务迁移，不重新初始化账号，不更换那五个原密钥。


## 版本化发布补充

当前交付增加package:tencent、update.sh和rollback.sh，具体命令见《版本化发布与回滚.md》。后续教程优先使用固定运行包，无需上传src或在服务器重做前端构建；首次安装与已安装更新分开。最近5版代码，数据库和配置持久化在release外。快照与部署台账在root私有/var/lib/yijiexingtu-deploy，不能改成yxt所有；无新增云资源、变量或模型设置。已提交迁移时自动回退只切代码并保持维护，不自动恢复库。首次接入更新器的旧版可能不含update.sh，教程需使用root临时解压目录启动更新。
