# 预演与正式切换操作单

本轮只准备程序和操作单，没有执行线上动作。控制台点击由Claude带领，服务器命令见README。准备期间不改DNS、不停原站、不删除原资源。

## 一、预演

1. 确认源系统为v0.5/0028，保存五个原密钥和原部署资料。
2. 完成带宽、安全组、两个上海COS私有桶及备份版本控制、绑定实例角色。安装服务器、配置env、证书、Basic Auth。
3. 用Mac导出D1；上传导出SQL。D1 Console执行 d1-row-counts-single-line.sql，将 counts JSON存为source-counts.json。
4. 导入rehearsal.sqlite，复制原R2媒体桶，并核对对象数、总字节和逐路径大小。
5. **同步历史备份原件**：新库会带着backup_runs历史记录；若不复制原R2备份桶，这些记录在新后台会找不到原件。因此用同样的copy/size/check方法，把原R2备份桶也复制到COS备份桶。只读R2令牌限定这两个源桶，不要给写权限。命令模板见README补充。复制后的对象修改时间可能成为COS接收时间，旧对象可能额外保留一个清理周期；非当前版本生命周期另在COS配置。
6. 两桶第一次复制核对完成后，**先记录预演前对象清单**（下面命令）。之后不要夹入其他复制任务；启动预演Node，只用预演库。
7. 访问两个域名的hosts预演地址，核对登录、学员/课时/财务、方案AI、图库、公众号、家长/分享、备份。真实模型和云连通验证由用户操作，不算本轮已测。
8. 运行verify并保留报告。在线预演时源可能继续写入：若源计数与导出快照因时间不同而不一致，不能写成通过；重新选择空闲窗口采集。**正式切换必须在冻结窗口严格相等**。
9. 演练《回滚操作单》的导出/导入及媒体反向复制，先对本机回滚测试库或临时D1目标，不在正式源库上清空演练。
10. 停止预演服务，预览并确认只清理预演新生成的COS对象。不要清空桶，不删除原R2，不拿预演库当最终库。

记录与清理命令（运行cleanup前必须停服务；预览不会删除对象）：

```bash
cd /opt/yijiexingtu/current
bash deploy/run-env.sh node deploy/rehearsal-storage.mjs record /root/yxt-migration/storage-before-rehearsal.json
```

上面是在预演开始前执行。预演结束时：

```bash
systemctl stop yijiexingtu
cd /opt/yijiexingtu/current
bash deploy/run-env.sh node deploy/rehearsal-storage.mjs cleanup /root/yxt-migration/storage-before-rehearsal.json
```

确认added列表确实只有预演新对象、且未开放真实客户写入，再执行：

```bash
cd /opt/yijiexingtu/current
bash deploy/run-env.sh node deploy/rehearsal-storage.mjs cleanup /root/yxt-migration/storage-before-rehearsal.json --confirm-rehearsal-only
```

工具保留清单里已有的对象，只删除预演新增对象。missingBaseline若不为空，表示预演删过原副本，正式增量copy会从R2重新补齐；不能把它误当成应该删除源对象。若缺少预演前清单、桶名不匹配、或有来源不明的新对象，不执行删除，先由负责人核对。

## 二、正式切换前

- [ ] 完整预演通过，包含回滚、解密、登录、COS权限、证书及真实AI。
- [ ] 通知机构停写窗口、预留至少1小时；不要承诺一定30分钟完成。
- [ ] 原Cloudflare Pages包、域名记录、Cron配置、数据库/媒体桶标识和可恢复备份已保存。
- [ ] 腾讯云预演服务已停，预演新增对象已按清单清理，最终源计数重新采集。

## 三、正式冻结和切换

1. 由用户把维护Pages包上传原Cloudflare Pages项目：根目录为_worker.js/index.html/_routes.json，**所有GET/POST都503**，不是仅换登录页。
2. **临时暂停原Cloudflare备份Worker的两条Cron，并确认没有正在写入的后台任务**。只换Pages不会停止它们；导出时仍有定时写入会导致计数不一致。保存原配置，不删Worker、D1或R2；这是导出窗口的临时冻结，7天稳定后再决定永久停用。
3. 核对原API所有业务写入被503拦住，旧已打开页面的保存也不能成功。
4. 重新导出d1-final.sql；在同一冻结窗口执行单行计数SQL，保存新的source-counts.json。不要沿用预演文件。
5. 导入新的crm.sqlite；增量copy媒体和历史备份两个源桶，重新核对。输出文件存在会拒绝覆盖，由负责人核对再选择新路径。
6. verify必须ok=true，外键/完整性、逐表计数、解密和图片全部通过。任何差异都先停止，不改目标数据来凑数量。
7. 启动腾讯云正式服务，DB_PATH明确指向正式库，查看自检Worker哈希、0028和role模式。启用快照/备份监测timer。
8. 用户按Claude教程把edu、ops改为A记录101.43.112.196、TTL600，核对HTTPS和域名分流；Cloudflare仍保持维护。
9. 验收两套登录、课时/财务、方案AI、图片、公众号、家长/分享。新系统只要有需要保留的写入（包括验收写入），回滚就走“已写入”路径。
10. 验收通过才通知机构恢复；启用公网健康timer。等待下一次03:00逻辑备份completed，04:00文件快照成功并做一次离线解密恢复核对。
11. 测试CPU/内存/磁盘80%、离线和日志ERROR告警渠道。没有实际收到测试通知不算告警接通。

## 四、稳定期

Cloudflare的D1、R2、Pages和原配置至少保留7天，不删除原数据或密钥。不要同时恢复两边对客户写入。R2读取迁移令牌保留到验收完成，之后删除；回滚写令牌单独按需创建并撤销。新COS备份版本生命周期和费用单独核对。
